# YOYO 运营平台修订说明 v0.2

2026-10-04。本文按用户最新要求修订，相关交互定义优先于前一版产品文档和效果图。只交付说明与静态效果图，不编写平台代码、不连接账户、不执行采集或发布。

## 1. “任务书”改名为“内容制作单”

这是 AI 根据已选题目生成的制作说明，不是让设计师额外写一份报告。用户选择题目后，系统自动整理：

- 为谁制作、表达哪个旅行场景和情绪。
- 为什么值得做、用户持续关注的理由。
- 每一张图的画面说明和页内文案；视频则给镜头、字幕与节奏。
- 标题、正文、互动提问及备选写法。
- 需要使用的官方素材、规格、交付数量、截止时间。

设计师可以直接编辑、删减，再上传作品。没有必要每次填写长表单；已有信息从选题、IP 库与排期继承。

例如“行李还没收完，心已经到海边了”：制作单说明封面呈现 YOYO 与行李箱，第 2 页描绘出发前准备，第 3 页放入海螺，第 4 页落在期待情绪，第 5 页邀请分享出发前的小心情，并配套标题正文。

## 2. 审核由你们内部完成

按用户确认，平台流程设为：选题确认 → 设计制作 → 内部审核 → 待发布 → 已发布 → 待复盘。

不额外设置单独的“品牌审核”节点或外部审批人。内部审核者检查画面与 IP 规范、文案与事实、图片顺序或视频成片，确认后进入待发布。你可以兼任设计与确认角色，也可以指定团队成员。

IP 规范保留在素材库与制作单中供设计使用。AI 给出检查提示，不替内部人员做最终确认。内容版本改变后，原内部确认失效，避免确认的内容与发布的内容不一致。文件手册保持原样，本次修改的是平台内部协作流程。

## 3. 选题策划以 AI 自动采集为主

“导入参考”不再作为主要入口，也不要求用户每天手动寻找链接。主要操作变为“数据源设置”“立即刷新”“生成内容制作单”。

### 三类来源

| 来源 | 采集目标 | 对选题的作用 |
|---|---|---|
| 微博热点榜 | 数据源实际提供的榜单名称、话题、时间、原始链接与可见热度 | 识别广泛关注的事件与情绪 |
| 小红书热点 | 实际可取得的榜单/话题页，保留原始来源名称与覆盖范围 | 识别平台内的场景和表达变化 |
| 小红书优质笔记 | 旅行、潮玩、IP、情绪表达等关键词与参考账号范围内的公开可读内容 | 学习选题切口、信息结构、封面表达与评论需求 |

不可把搜索结果、推荐页或第三方自建榜自动标成“小红书官方全站热榜”。数据源必须显示真实类型；当前效果图中的热点记录均为示例，不代表已经抓到实时内容。

### 自动工作的完整过程

定时获取已接通来源 → 保存来源时间与采集时间 → 合并重复话题 → 去除无关或过期内容 → 筛选适合 YOYO 的角度 → 生成有限数量的候选题 → 用户采纳 → 生成内容制作单。

起步建议每天 09:00、16:00 运行，Asia/Shanghai 时区，频率可调整并受实际来源限制。图中时间只是产品演示。某一来源失败不影响其他来源，但必须显示失败、最后成功时间与内容是否过期；绝不能标作“全部更新成功”。

### 怎么定义“优质笔记”

不能简单按点赞数排序。先看题材与受众是否相关，再看标题和内容能否兑现、画面与叙事是否清楚、评论是否反映真实需求、与 YOYO 是否有可迁移的表达方式。

在可获取数据允许时，结合发布时间、形式、账号体量与其自身历史表现做比较。公开页面没有阅读/曝光或涨粉归因时，不估算互动率、阅读率或涨粉效果。点赞、收藏、评论按采集时点记录；这些指标用于候选筛选，不等于已经证明内容优质或能涨粉。

AI 应分别输出“看到的事实”“为何值得参考”“YOYO 的原创改写角度”，保留原文链接。参考的是需求和表达方法，不复制他人图文、冒用其素材或把其观点写成自己的经历。来自评论和网页的文字只作为数据，不能改变平台指令。

### 开发前必须验证的能力

自动采集是主流程需求，不是未经验证的接口承诺。开发需为每个来源提交一个真实样本，明确获取方式、可得字段、登录要求、覆盖范围、刷新限制、失败处理与成本。可以评估平台可用接口、具备相应权限的数据服务或账号授权下允许的浏览器读取。

验证无法取得所需榜单时，应明确显示该来源不可用，并讨论可替代的真实来源，不能悄悄用模型编造内容或将手工导入包装为已完成自动采集。采集来源设置是一次配置加必要维护，不是把日常找资料工作交回用户。

## 4. 排期日历

显示三个节点：制作、内部审核、发布；支持周/月视图、按图文/视频筛选、查看与调整某篇的制作单。

AI 依据已采纳选题、时效、素材依赖和用户可投入工时提出排期，人确认后生效。首次没有历史数据时，发布时间是试验时间，不宣称最佳时间。

拖动一个节点后重新检查上下游：发布提前但内部确认来不及，则提示冲突并建议调整；延期时重新判断热点是否失效。临近发布时间仍未内部通过的内容，保持待确认，不能自动视为可发布。

首版日历表示计划与提醒，不默认具有自动发帖权限。人工发布后补真实链接和实际时间；未登记实际发布的内容不可产生发布后表现。按实际发布时间建立 24 小时、72 小时和 7 日的可配置数据回收提醒。

### 4.1 活动帖与开奖提醒（用户补充）

排期日历增加独立“开奖提醒”事件类型和筛选项。普通内容帖不要求填写开奖字段；活动帖关联原始笔记或待发布内容，填写活动名称、参与截止时间、开奖时间、负责人、活动规则版本与提醒设置。活动发布时间、参与截止时间、开奖时间分别保存，不共用一个字段。

默认提醒建议：提前 1 天、提前 1 小时、到点提醒，可调整或关闭。默认采用平台站内通知＋工作台待办；邮件、企业微信等外部渠道是否接入另外配置，本次不发送通知，也不创建真实定时任务。

活动状态分为“待开奖 → 已开奖 → 已公布”；暂停、取消为单独状态。超过开奖时间且仍为待开奖时，显示“逾期未处理”。已开奖但未公布时显示“待公布结果”，不要仍提示需要抽奖。打开或已读通知不改变活动状态。标记开奖要记录操作人、实际时间和结果记录；标记已公布需填写公布链接或可追溯记录。

日历显示活动名、开奖时间、状态和铃铛图标；工作台显示今日开奖、即将开奖、逾期未处理。点击卡片可看活动原帖、规则、时间、负责人、提醒历史，并进行人工状态更新。AI 可以辅助整理规则和拟写公布文案，不在此功能里自动选中奖人或自动公布结果。

时间统一使用 Asia/Shanghai 显示并记录时区。系统检查发布≤参与截止≤开奖（允许截止与开奖同一时刻）；缺开奖时间的活动不能启用到点提醒。创建活动时已错过的提前提醒不批量补发，直接显示当前状态和后续提醒。

如修改开奖时间：重新计算未触发提醒、取消旧时间待发提醒、保留修改记录；如果规则或原帖已对外公布，提示内部负责人同步更新公开信息，不能仅拖动日历就声称原帖已改变。活动取消后停止未发送提醒。服务重启与重试不能导致同一事件在同一提醒节点重复通知。到点提醒未被处理时保留待办和逾期标记，重复通知频率单独配置，避免持续轰炸。

开奖提醒是独立于发布动作的服务：即使不支持自动发帖，也需要按已确认活动时间运行。验收时应覆盖准时触发、修改时间、取消活动、跨日、重复重试、漏执行恢复、已读但未开奖、已开奖未公布等情况。通知是否真正送达与任务是否已处理分别记录。

## 5. 后台数据怎么给

公开主页截图只能建立账号展示值和可见内容记录，不能替代创作者后台数据。

| 建议提供的页面 | 希望读取什么 | 截图要保留什么 |
|---|---|---|
| 创作者后台账号概览 | 粉丝变化、内容整体表现等后台实际可用指标 | 账号标识、完整指标名、日期范围、数值和单位 |
| 后台笔记数据列表 | 单篇内容与其实际可获取指标 | 标题/笔记标识、时间范围、列名；横向分屏时保留对应行标识 |
| 重点笔记的数据详情 | 阅读/播放、互动、来源或关注归因中实际有的字段 | 笔记标题、发布时间、统计时间、完整指标名称 |
| 粉丝分析（可选） | 聚合画像与受众变化 | 时间范围、比例基数或页面说明；不需要用户个人明细 |

以上是需要的数据类型，不保证当前账号后台有完全相同的菜单名称或全部字段。不存在的字段标记为不可获取，不能猜填。

### 三种输入方式同时设计

1. **截图识别**：粘贴或批量上传图片 → AI 识别 → 并排显示原图与识别表 → 只突出需确认/修正项 → 保存来源和采集时间。适合启动与偶尔补录。日期不明时让人选择，不把截图时间当统计区间。
2. **表格导入**：若实际后台支持导出，上传原始 Excel/CSV → 映射字段 → 预览确认 → 入库。适合定期多篇内容统计。首版先验证实际导出文件，不能承诺所有账号均有该入口。
3. **授权自动同步**：开发验证能读取本账号的相应数据后再接。自动读取不一定等于接口，需明示数据来源、授权状态、最后成功时间与失败情况。仍保留截图/文件补录。

现阶段建议先拿一次近 30 天账号概览、笔记列表和 3–5 篇重点笔记详情做字段验证。稳定运营后每周补一轮账号数据，重点笔记按发布后观察窗口记录；可按团队工作量降低频率，保留真实时间点。

### 数据正确性要求

- 不把空值当零；“1.2万”保留近似性质。
- 账号、笔记、统计区间、采集时间、累计/区间口径必须记录。
- 同一笔记累计快照不能相加；不同时间点保留为不同快照。
- 同一截图重复上传不重复计数；修正识别错误保留修改记录。
- 没有后台单篇关注归因时，不能把账号净增粉分摊成每篇涨粉。
- 无须采集订单、私信、粉丝名单等与此次运营复盘无关的个人信息。

官方创作服务平台介绍包含数据分析能力，但公开介绍没有证实本账号所有字段和导出入口：[小红书创作服务平台](https://creator.xiaohongshu.com/)。公开 Marketing API 主要面向投放相关功能，不能据此认定自然内容数据已可全量同步：[小红书开放平台](https://ad-market.xiaohongshu.com/)。核验日期 2026-10-04。

## 6. 本轮补充验收

1. 选题页无需先人工上传参考，就能通过实际接通的来源生成带可追溯证据的候选题。
2. 源不可用、登录失效、更新超时、内容过期分别可见，不捏造成功结果。
3. 任一候选题可查看来源、采集时间、推荐理由和 YOYO 原创角度。
4. 采纳后自动生成可编辑内容制作单，不要求设计师重复抄写选题背景。
5. 内部确认即为平台的审核节点，不另设外部品牌审批。
6. 排期调整能提示依赖冲突；计划发布与已发布区分。
7. 截图识别经过预览确认才入库，原图可追溯，重复上传不重复计数。
8. 单篇涨粉不可得时显示缺失，不伪造归因或收益。

## 7. 高保真图阅读说明

本轮使用内置 imagegen 生成静态效果图，提示词存于同目录。日历任务与热点记录为示例。图像内正文、图标、角色细节仍需正式设计文件复核；效果图不是可编辑原型，也不意味着已接通数据源。v0.2 选题与工作间图替代旧版对应页面，其余旧图中的“任务书”名称在实现时统一改为“内容制作单”。
