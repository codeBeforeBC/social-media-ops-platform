# 运行状态页面重设计

用户选择“异常与待处理事项优先”。沿用YOYO现有字体、绿色主色、圆角与离线字体，不增加图表、依赖、接口或自动刷新。实际任务状态仅见[开发进度](../tracking/开发进度.md)。

## 阅读顺序

1. **待处理事项**：置顶摘要，按进程未响应、历史失败/部分完成、来源待核对、AI配置不可用分类，提供查看进程/任务/来源/设置入口。正常时收为简洁概览，不展示空问题清单。
2. **当前任务与进程健康**：宽屏并列。任务只突出运行、等待和待分发数量，历史分布折叠；进程只突出用途和响应状态，标识/执行池/完整响应时间折叠。
3. **AI与实际用量**：模型与配置状态、UTC当日调用及已知token为主；预算/价格为次级信息；按币种的费用、未知用量和预算上限在明细中查看。人工OCR核对边界保留。
4. **来源连接**：健康、暂停和定时开关分开表达；名称链接到来源，最近成功可扫读，配额/计划/最近错误按需展开。

## 表达边界

- 历史失败/部分完成需要核对，不计入当前运行数；等待和待分发不自动当作故障。
- 无心跳时明确无法判断；显示“已上报进程”的响应情况，不据此证明模型或平台已连通。
- 关闭定时和禁用AI为配置选择，不单独生成故障提示；来源未验证、登录失效或受限需核对。
- AI已启用只表达配置，调用可用性仍需验证；未知用量/价格/费用不补零，不混加币种。token聚合保留整数精度，费用保留后端原始小数文本。
- 数据来自手动刷新的时间点，显示采集时间，不冒充持续实时监控。

## 布局与交互

去除承载所有内容的单一大白框，以独立分区和适当留白建立层级。异常用柔和琥珀色与文字共同提示，正常概览用现有绿色；不单靠颜色传达状态。主次字号为24/17/12–13px，关键任务数量为26–30px。

1050px以下任务/进程单列；600px以下重排模型与指标，主要操作入口与展开摘要提供44px触控区域。长来源名允许换行，只有明细表在具名、可键盘聚焦的区域内横向滚动，整页不产生横向溢出。

折叠使用原生details/summary，键盘可展开；进程入口聚焦并滚动至本页对应分区，不使用会触发路由的内部hash。保留BUG-041的按页签组件隔离及请求失败重试，防止运行状态与审计互切复用旧数据。
