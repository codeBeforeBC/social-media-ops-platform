# CHANGE-029 账号验证与保存交互优化

2026-10-30；依据用户对按钮堆叠、技术字段过多、历史排版及“运营确认/保存修改混淆、保存后应关闭”的反馈。实际状态只维护于[开发进度](../tracking/开发进度.md)。

账号详情先呈现当前验证结论：匹配、验证中、需登录、登录错号、过期或暂不可确认；其次呈现主页与登录两项结果、平台昵称及最近观察时间。后台指标保留是否验证的边界。绑定版本、会话ID、三组请求/执行时间不在普通界面堆叠；旧成功不覆盖最新失败或新绑定。

操作按目的分区：

- 验证区只有一个主要验证入口；在途可取消，保留冷却和失败重试。选择工具改称“验证所用浏览器”，默认收起“更换浏览器”，用“确认更换”应用，不再出现“保存浏览器档案”。
- 人工确认区说明“将此账号用于工作区运营”，勾选后“确认用于运营”；它只保存人工声明，不证明平台授权。成功关闭详情，列表显示独立成功提示与已确认状态。
- 普通备注默认收进“修改本地备注”，展开后使用“保存备注”，明确只改列表名称；失败保留输入，成功关闭详情并在列表提示。它不确认账号管理，也不修改绑定或时区。
- 新增只有“添加并验证”，成功提交后关闭弹窗并提示“账号已添加，验证请求已提交”；不等待或假设验证通过。列表在存在排队/运行验证且详情关闭时自动读取结果，终态停止；失败保留账号，详情可重试。

验证历史默认折叠，展开后用时间线显示时间、状态和可理解的结果/失败建议，分页和重试保留。当前在途记录随最新结果更新；不显示技术错误码和绑定版本。浏览器设置、历史与备注各有独立层级，窄屏单列和键盘展开。

实现沿用React、原生details及现有接口；无新依赖、迁移或平台接入。覆盖新增/编辑/运营确认成功关闭、失败保留、名单轮询终止/失败恢复、错号/过期/历史与更换浏览器冲突、多宽度及删除回归。受控测试与真实只读验收分开记录，不对用户实际账号运行验证、确认或删除；本轮[证据](../evidence/change029/README.md)。
