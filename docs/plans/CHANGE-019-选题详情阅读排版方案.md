# CHANGE-019 选题详情阅读排版方案

2026-10-27；Codex。范围是用户要求的排版构想，未实施到产品。状态事实仅见开发进度台账。工作目录 `/Users/junlong/projects/social-mdeida-ops-platform`，分支 `codex/s9-acceptance`，HEAD `9ae84f7` 加既有未提交修改。

## 阅读目标

用户从候选列表打开抽屉后，应能依次回答：这是什么题，为什么值得做，依据是什么，哪里还不确定，是否采纳。当前520px抽屉把连续文字、六项评分、假设、缺项与历史等量罗列，内容主次不明，按钮在长文本后不易找到。

建议保留右侧抽屉，桌面宽度约800–840px，最大不超过可视宽度；窄屏全宽。沿用实际产品的森林绿、白色和中性色，不以旧设计文档的蓝白描述覆盖当前样式。仅此选题详情加宽，不改变生成选题、来源等其他抽屉。

## 页面结构

| 顺序 | 模块 | 阅读方式与已有字段 |
|---|---|---|
| 固定顶部 | 标题、关闭 | “选题理由与证据”和关闭按钮；关闭后焦点回到触发入口 |
| 首屏摘要 | 这是什么题 | 状态、图文/视频、完整标题；一行次要信息展示建议总分、引用条数、制作工时/待估；有父题则提供真实父题入口 |
| 主阅读区 | 这个选题，值得做在哪里 | original_angle为主要段落，使用柔和底色强调；audience与need合为“写给谁·解决什么需求”，scene为“在什么场景下读”，follow_reason单独说明持续关注动机 |
| 依据区 | 选题依据 | evidence按已有fact/inference/original_hypothesis明确分组；fact显示引用原文、原始来源标题/链接、captured_at；推测与原创假设不能被包装为来源结论 |
| 风险区 | 假设与待核验事项 | assumptions、missing_inputs、warnings分别标记“选题假设”“待补信息”“注意事项”；去除完全相同文本的重复展示，不隐藏不同风险；有过期提示则置于摘要下，不能折叠 |
| 次要详情 | 评分解释 | 默认折叠；展开后六行，每行维度、0–5分水平条、完整评分理由；总分仍使用服务端score，不在前端重新计算。说明评分只用于比较，不代表爆款概率 |
| 次要详情 | 决策记录 | 默认折叠，显示记录条数；展开按时间展示已采纳/已拒绝、原因、时间，无记录给出简洁空态；保持API真实记录 |
| 固定底部 | 决策操作 | “采纳选题”为唯一主要按钮；“拒绝并留因”次要，“创建变体”低强调。附一句“采纳仅保存决策，内容制作与发布在系统外完成” |

不将各段全部拆为同样大小的卡片。通过留白、段落标题、轻分隔线建立层级，仅原创角度、引用和待核验提示使用有明确目的的容器。首屏评分处于次要位置，避免用户只看分数就采纳。

## 交互与状态

- 内容保持单页阅读，证据和风险不放到隐藏标签页。顶部与操作底部在实际抽屉中保持可见，中部只有一个滚动区域；底部不得遮挡最后一条内容。
- 保留当前采纳前确认；确认内容在同一抽屉中展开，提供取消。拒绝填写原因，变体保留目标及形式选择；不创建第二层抽屉，不改变现有API及expected_version规则。
- 只有effective_status为proposed时显示现有采纳/拒绝操作。已采纳、已拒绝、已过期显示真实状态；创建变体沿用现有可用条件，不借排版引入新权限或限制。已采纳且证据过期保留原决策并显示重新核验提示。
- 无证据显示“无来源引用，按原创提案核验”，不虚构来源数、来源平台或来源链接。原文存在不证明真实性；captured_at只标为观察时间，不当作发布时间。
- 假设、缺项与警告分别为空时隐藏对应空分类；全部为空可用一行“当前未列出待补项”，不得声称已完成全部核验。工时null继续显示待估。
- 本轮使用已有字段重排，不额外调用AI生成一句话总结、事实核验或推荐结论。现有follow_reason/original_angle的主张按原文展示，不拆改导致语义变化。
- 长标题、长理由、原文段落和无空格文本换行；正文建议14–15px、宽松行距。桌面的人群/场景区域双列，窄屏单列，按钮换行；评分仍保留分值文字，不只靠颜色。
- 错误与409冲突提示必须出现在抽屉可见区域，提交期间按钮禁用，失败保留用户填写；不要把后台错误留在被遮罩盖住的列表页。
