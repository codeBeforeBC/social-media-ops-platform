# CHANGE-014：本地单实例、默认用户与免登录改造规划

日期：2026-10-25（Asia/Shanghai）。代码核对基线：`codex/s9-acceptance` / `c993d0f`。本文是实施规划，不是功能完成或迁移成功报告；实际状态只维护在[开发进度](../tracking/开发进度.md)。

## 1. 需求与使用结果

每位使用者在自己的电脑上运行独立实例，不需要工作台内部的用户区分。打开本地网页直接进入工作台，不填写邮箱、密码或初始化凭据，不出现登录、退出、邀请成员或切换用户入口。

每个实例自动拥有一个稳定的默认用户和默认工作区。它们只是现有业务归属、任务和审计所需的内部标识；不同电脑独立保存各自的数据，不共享默认用户的业务内容，也不增加云端账户或跨实例同步。

本需求替代CHANGE-012中“个人登录、邀请、同工作区全员管理员”的产品要求。CHANGE-012的迁移与验收记录仍是历史事实，不删除旧证据。术语见[CONTEXT.md](../../CONTEXT.md)。

### 直观变化

| 场景 | 改造后的行为 |
|---|---|
| 全新安装 | Docker完成迁移和默认上下文初始化后，打开网页即进入空工作台 |
| 已有实例 | 无需再次登录，直接看到原工作区、运营账号、来源、笔记和数据 |
| 清除Cookie、换浏览器、重启电脑 | 仍使用同一默认身份和数据，不重新创建工作区、不出现登录页 |
| 多标签页操作 | 共用同一实例内容；保留版本冲突和幂等保护 |
| 修改工作区名称、时区 | 在普通工作区设置中修改，不作为首次进入门槛 |
| 连接平台账号 | 平台侧登录、授权、Bridge和模型密钥仍按各自能力配置 |

## 2. 范围与保留项

删除工作台内部的登录、退出、邮箱密码设置、成员邀请/接受邀请、成员列表/停用/移交、角色展示、个人资料抽屉、登录过期倒计时和跳转，以及新增业务的负责人选择。来源、运营账号、选题采纳等新记录自动归属默认用户。

保留三导航、来源与定时/手动采集、笔记登记、文件和导入、复盘、反馈、系统通知、操作审计、任务重试/取消、时区和预算设置。CHANGE-013的手动/定时解耦及暂停/间隔规则继续有效。

保留服务端工作区、运营账号、文件用途和引用关系校验，以及Origin/CSRF、私有签名、URL校验、解析沙箱、幂等、版本控制和预算守卫。取消登录不等于所有资源ID都可被任意互换。

本轮不提供共享服务器、多用户、用户切换、公网免登录部署或跨实例同步；不删除历史用户及其业务记录，不把被取消的资产/制作/日历/活动模块恢复回来。

## 3. 当前实现为何不能只隐藏登录页

已核对代码的关键耦合如下：

| 位置 | 当前依赖 | 需要的调整 |
|---|---|---|
| `apps/web/src/main.tsx` | 先查setup/status，再查me，按登录状态显示Auth或Shell | 改为读取实例上下文，直接显示Shell；保留服务初始化失败/重试状态 |
| `apps/web/src/api.ts` | auth/csrf、401触发session-expired、退出清令牌 | 分离请求令牌与登录；不再跳登录或提示账号过期 |
| `apps/api/src/auth.ts` | actor从Cookie/登录session/成员角色获得身份 | 改为从持久默认实例映射解析业务上下文 |
| `apps/api/src/commands.ts` | command事务内reloadActor再次检查登录session | 事务内重读默认映射，保留幂等和并发保护，移除登录session依赖 |
| API列表/详情与文件路径 | workspace_id、account_id、成员及文件用途校验 | 当前工作区只能由服务端映射获得，继续验证资源归属 |
| worker/媒体/AI/导入处理器 | 从created_by查成员，提交时验证active/roles及业务快照 | 新任务用默认用户；旧任务保留原归属并按明确兼容规则运行 |
| 通知/审计/幂等表 | recipient_id、actor_id及组合外键 | 保留历史ID和密文，新写入统一使用默认用户 |

仅给请求对象临时填一个admin或跳过authorize并不能解决事务重读、后台任务、通知和冷启动；也不能每次请求重新创建默认用户。

## 4. 默认身份与工作区

### 持久映射

在`instance_state`新增默认工作区与默认成员的持久映射，成员再关联内部用户。通过外键保证三者属于同一上下文；ID为实例内生成或沿用的UUID，不使用各电脑共用的固定业务ID。

业务请求和后台调度从该映射获取上下文，不接受客户端通过Cookie、请求头、query或body指定当前用户。客户端仍可选择本工作区中的运营账号，但无法借`workspace_id`访问另一个工作区。

映射建立使用事务和实例级锁；API/worker/scheduler就绪前完成。并发启动只创建一份，重复迁移、重启和容器重建不改变映射。映射缺失或引用不一致时服务不宣称就绪，页面提示检查初始化，不退回登录流程。

### 新装与升级规则

| 数据情况 | 处理规则 |
|---|---|
| 空库 | 自动创建“我的工作台”和“本地使用者”，默认Asia/Shanghai，写入持久映射 |
| 已有唯一工作区且唯一有效成员 | 直接沿用其workspace/user/member ID、工作区名称、时区和设置；不另建空间、不挪数据 |
| 唯一工作区但无有效成员 | 创建无登录能力的默认身份；原停用身份与历史引用保留，不批量复活旧成员 |
| 已存在有效默认映射 | 校验后复用，不按新增或更早的成员重新选择 |
| 旧库存在多个工作区或多个有效成员且没有默认映射 | 升级预检报告歧义，要求维护者显式指定既有工作区/成员；不按第一条记录猜测，不合并或覆盖业务空间 |

最新交接记录的实际使用实例为一个用户/成员，正常升级应走沿用路径；本轮规划未重新查询实际数据库，不将交接记录当本次升级证据。

新建默认用户不生成可用密码，也不提供默认公共密码。建议新增迁移允许`users.password_hash`为空，仅供无登录能力的内部身份；已有密码哈希原样保留在受限数据库，不经接口暴露。若保留users.email的历史非空约束，新默认记录自动生成不可投递的内部占位邮箱，不展示、不要求填写真实邮箱。先保留users/memberships与现有外键以降低迁移范围，不为免登录重写全部业务表。

内部兼容Actor可以继续承载默认user/member/workspace及全量业务能力，但不再把角色作为用户可配置的产品概念；`sessionHash`不再成为业务写入或Job提交的身份前置。

## 5. 请求保护与本机边界

- 宿主机发布端口继续绑定回环地址；Docker容器内部API监听`0.0.0.0`用于容器通信，不等于向局域网开放宿主端口。
- `APP_ORIGIN`匹配实际localhost/回环访问地址；本版不沿用公网上线模板承诺。新增启动/配置预检，拒绝将免登录实例直接作为公网或局域网服务发布。
- 在浏览器入口校验受支持的Host，阻止任意Host/DNS重绑定；不信任未经配置的代理转发头。不以容器内看到的客户端IP是否为127.0.0.1作为唯一判断。
- 写请求继续校验精确Origin、请求令牌和Content-Type；不放开跨域读取或写入。文件分片上传、签名创建和下载代理也纳入边界检查，已签名原件仍需短期签名。
- 保留匿名技术会话/CSRF令牌以保护本机接口；它不关联登录用户，不要求使用者输入或选择。新浏览器可自动取得，过期后刷新请求凭据或提示重试，不展示登录页，不自动重放未经确认的业务提交。
- 数据库、对象存储和解析器仍使用私有凭据；Bridge鉴权、平台侧登录和AI密钥保持。旧邀请响应的内部加密密钥不因删除邀请入口而轮换或删除。

这个模式把本机访问者视为实例使用者，不提供同一台电脑上不同自然人之间的权限隔离；审计证明业务发生过何种变化，不证明具体哪位自然人操作。

## 6. 页面与接口调整

### 页面

启动流程改为“实例上下文加载 → 三导航工作台”；首次进入仅显示业务空态，可引导配置运营账号，但不要求先创建个人账号。右上角只保留通知等业务入口；工作区设置去掉成员和用户资料。

“我的通知”改为“通知中心”；选题采纳和来源/运营账号创建不再要求选择人。工作台欢迎语改为“欢迎使用YOYO”或业务进度描述，不展示邮箱、角色或账号过期状态。

删除负责人字段的输入能力，并对旧客户端提交的`owner_id`/成员选择字段给出明确契约错误；新写入由服务端填默认身份，历史负责人仍能在记录中保留。不要静默接受客户端伪造的默认成员ID。

### API目标

以下路径均相对于`/api/v1`，最终与契约生成器同步：

| 路径 | 目标 |
|---|---|
| 新`GET /instance` | 返回默认工作区、时区及实例运行模式，不返回邮箱、角色、登录有效期、内部密钥或可任意选择的用户 |
| 新`GET /request/csrf` | 无需登录获取浏览器请求令牌；验证Host/请求边界，技术Cookie不作为业务身份 |
| 原`/setup`、`/setup/status` | 退出，统一返回410及清晰错误，不保留可再次创建身份的接口 |
| 原`/auth/login`、`logout`、`accept-invite`、`session`、`csrf`及`/me` | 退出，返回410；新前端不再依赖这些接口 |
| 原`/members`及其详情/修改接口 | 退出，返回410；不保留隐藏的邀请/停用/权限写入口 |
| 保留的来源、选题、笔记、导入、报告、文件、设置、通知与任务接口 | 默认实例上下文可直接读；写入仍需Origin/CSRF与原业务守卫 |

旧接口410规则应在身份解析之前生效，避免先返回401再跳登录。现有登录Cookie不再授予或决定身份，旧已登录/未登录浏览器的业务内容一致；旧会话在迁移时失效，不能使默认上下文切换。

OpenAPI的sessionCookie登录安全声明、Setup/Login/Member等当前输入输出Schema及示例清退，保留CSRF与本机调用说明。同步TypeScript类型、测试客户端、Compose/原生/发布冒烟脚本及运行说明；删除无调用的Argon2依赖和密码工具，不通过旧密码自动登录实现免登录。

## 7. 历史数据、通知、幂等与后台任务

**历史身份不删除、不批量改写。** 保留来源、笔记、导入、指标、报告、任务、审计、文件以及其user/member/workspace/account UUID。旧密码/邀请表可作受限兼容留存，没有产品读取/写入入口；物理清理不纳入本次改造。

**新操作统一归属。** 新created_by、owner_id、recorded_by、actor_id及通知收件人由默认映射填充。已有业务对象的原操作者/负责人不为统一显示而覆盖，更新对象也不重写原创建人。

**通知成为实例通知中心。** 读取本默认工作区的历史通知，不再只按默认成员过滤。历史多收件副本可按event_key/channel合并展示，标已读同步该工作区同事件副本；保留原recipient_id、事件和Job关联。不得因默认身份改变使旧通知消失，也不能把已读当作任务完成。

**幂等保留原语义。** 复用原成员ID的实例沿用其幂等键命名空间和加密密钥。历史其他成员的记录不改键、不合并；新操作只使用默认成员命名空间。升级应保留重复写入冲突保护，不借统一身份重复采纳、重复确认或重复发通知；已退出的邀请/成员接口不因旧幂等缓存重新开放。

**不伪造在途任务的原发起者。** 切换时停止API写入、worker和scheduler并取得同点备份，确认无旧进程持有租约后再迁移。新任务由默认身份发起；旧Job和Outbox的created_by、业务输入及来源版本保持：

1. 原发起者属于所选工作区且仍满足保留的兼容成员/资源条件时，旧任务可按原记录恢复，不能再依赖浏览器登录session存活。
2. 原发起者无效、属于未选工作区或权限/输入已经变化时，不通过重写created_by绕过守卫；任务明确失败/取消并保留原因，允许本实例使用者核对后重试。
3. 取消、预算、证据版本、文件用途、来源暂停、同源并发和最小间隔保护保持。通知中心同时能看到旧任务和默认用户新任务的结果。

## 10. 上线切换与回滚

实施阶段先在可重置测试库及旧库副本验证，再盘点实际使用实例、停止全部写入进程、备份DB/objects/state，执行新增迁移并统一更新API/worker/media/scheduler。完成默认映射和数据核对后才恢复自动调度；保留用户原定时开关，不能顺带开启来源或调用模型。

对照升级前的UUID、关系、业务值与文件hash验证；默认映射和技术会话属于允许变化的结构，历史身份/业务归属及原件不应被静默改写。首次打开工作台无需再次创建账号，也不把真实数据搬进测试实例。

回滚以停写后恢复升级前同点备份和对应旧构建为确定路径；不假定旧登录程序可直接运行在新迁移后的库，不把恢复应用镜像当作恢复数据库。备份后新增内容的损失范围必须明确。

规划编制轮（LOG-108）只交付本文、相关需求基线和台账同步；后续实现、039迁移、验证与部署事实以开发进度和开发日志为准，不在本文维护第二套状态。
