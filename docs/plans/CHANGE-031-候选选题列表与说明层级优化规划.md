# CHANGE-031 候选选题列表与说明层级优化规划

2026-10-30；Codex；工作目录 `/Users/junlong/projects/social-mdeida-ops-platform`，分支 `codex/s9-acceptance`，基线 `34317f8` 加既有未提交修改。用户要求先给出规划，本文件定义后续实施范围和验收，不表示产品已改版。任务状态只在[开发进度](../tracking/开发进度.md)维护；交接见LOG-167/168。

## 1. 目标与现状依据

列表支持快速回答“这是什么题、准备从什么角度写、要先核对什么、是否值得打开详情”。完整论证与评分留在详情，整批生成的局限集中解释。

已核对的截图样本：两题属于同一生成批次；六条批次missing_inputs被复制到每题，系统再追加“制作工时待估”。卡片摘要另显示工时待估，共形成三次同义提醒。两题各有一个去重参考来源，三条依据记录分别属于事实摘录、AI推断、原创假设；“3条引用”容易被理解为三份独立证据。二者当前均过期。

该批生成快照的50条来源均无摘要，已激活策略为空，未携带画像、历史内容、效果指标和实际工时。对此只能说明“本次生成未参考这些资料”，不能断言用户没有录入，也不能将系统尚未接入的输入列成用户必须补齐的任务。

## 2. 页面结构与默认行为

保留选题页当前其他区域，只调整“候选选题”区及对应详情；不重排来源区或新增导航。

1. 标题与操作：候选选题；“生成候选”为主要入口，“刷新”为次要入口。
2. 筛选：沿用账号、状态、形式三个筛选。首次进入建议默认“待采纳”，筛掉派生过期项；用户选择其他状态后刷新/分页保持选择。已有明确状态深链或恢复状态优先，不强制覆盖。
3. 生成说明：存在已知批次限制时显示一行中性说明与“查看生成说明”，默认收起；不展示“还差7项”或红色缺项告警。
4. 候选列表：桌面、平板和手机默认单列紧凑条目；不增加卡片/列表切换偏好。
5. 加载更多：沿用真实游标，不将当前已加载条数当总候选数；追加不重置筛选/滚动或重复批次说明。

首次无待采纳项时显示“暂无待采纳选题”，提供“生成候选”和“查看历史选题”；不自动发起AI生成。已有候选的读取失败要保留列表并显示重试，不能误报空列表。快速切换筛选时迟到响应不得覆盖新结果。

## 3. 列表条目的具体设计

| 顺序 | 常显内容 | 规则 |
|---|---|---|
| 1 | 状态、图文/视频 | 待采纳/已采纳/已拒绝/已过期独立于内容风险；颜色配文字 |
| 2 | 完整标题 | 视觉重心，建议16–18px；常规标题1–2行，异常长标题允许增高，不为等高切掉标题 |
| 3 | 写作角度预览 | 直接用既有original_angle，最多2行加省略；不额外调用AI改写，详情保留全文 |
| 4 | 参考来源、必要核验提示 | 来源按去重source_item_id计数；仅保留与本题有关、可核对的简短提示 |
| 5 | 查看选题 | 唯一决策入口；打开详情，不在列表直接采纳或拒绝 |

移出列表：完整关注理由、人群/需求/场景、完整待补段落、AI评分、未知工时和“制作工时待估”。它们按后文规则进入详情或生成说明，不丢弃历史原始数据。

条目不再设置大面积绿色/黄色底色。白底、轻边框或分隔线，状态与少量风险使用局部强调；维持现有绿色主色和页面字体。桌面操作靠右，手机操作自然换行；不把整条目做成不可选择文本的点击容器。普通条目以明显少于现有长卡片的高度呈现，不用固定高度隐藏异常内容。

## 4. “待补”的重新分层

不再把所有内容统称为待补，也不要求列表出现一个没有完成路径的“补资料”按钮。

| 现有信息 | 新位置与表达 | 是否要求用户立即完成 |
|---|---|---|
| 本题仅参考标题、事实细节不充分 | 列表“需核对原文”；详情常显“发布前请核对原始报道/具体事实”与真实来源入口 | 涉及事实时应在使用前核对；不新增自动审核门槛 |
| 真实工时不足、制作工时待估 | 列表不显示；批次说明一次解释“本次未提供可靠制作时间估算” | 不要求用户在不存在的表单补值 |
| 画像、历史表达样本未进入输入 | 批次说明“本次未参考读者画像/账号历史内容” | 属于建议适用范围，不是报错或必填 |
| 效果指标未进入输入 | 批次说明“本次评分未参考历史效果” | 不在列表逐题催用户导入数据，不承诺导入后自动用于生成 |
| 没有有效编辑策略 | 批次说明“本次未使用已启用的运营经验” | 可正常生成和查看，不包装成故障 |
| 本题具体假设和其他警告 | 详情常显“使用前核对”；列表提示存在额外说明 | 根据原始含义判断，不自动标记已解决 |

本题核验提示优先级：时效状态独立展示；来源/事实需要核对的提示其次；其他说明再后。列表常规只显示1–2个简短提示，超出时说明“另有N项核验说明”，完整内容在打开详情后常显。提示数量不是风险等级，不显示没有依据的“可信度高/已核实/全部安全”。

有原文片段不等于内容真实；没引用外部事实的原创提案不强行要求补新闻正文。仅有来源引用但无事实摘录时，仍称“参考来源”，不称“事实依据”。自由文本无法可靠归类时，保留到详情常显事项并在列表提示，不用关键词匹配将其静默丢弃。

## 5. 共用说明、来源计数与数据处理

### 共用说明按真实生成批次读取

从对应ai_requests的已保存结果取得批次missing_inputs/warnings，从当时快照确认实际带入的资料范围。列表API附带当前已加载条目涉及的最小生成说明映射；沿用已取消素材/品牌/审核/排期等旧范围过滤，不把旧缺口重新带回普通界面；不依赖“当前两张卡片文字一样”来猜整批相同，不跨账号或批次合并缺口。

只有一个批次时说明“本次生成”；混合批次时“查看生成说明”展开为按生成时间区分的记录，每题详情明确对应哪次生成。筛选/翻页后只列当前已加载项涉及的批次，去重追加，不冒充全量汇总。历史变体继承生成上下文时显示真实父题/批次关系，不把变体创建时间冒充AI重新生成时间。

优先按已保存批次结果的原始条目识别共用项；“制作工时待估”等系统追加项按明确规则去重。旧批次缺少可读记录或无法确认归属时显示“历史生成说明不完整”，保留原题说明，不伪造资料齐备或使用当前账号数据回写旧快照。

来源核验提示只依据本题实际引用的冻结资料：作为事实引用的来源存在只有标题且摘要为空的情况时，提示“需核对原文”。不能因为整批某条来源缺摘要就给每题都加同样标签；资料无法读取时保持未知，不推断正文齐备。

### 来源计数统一

列表和详情都按实际非空source_item_id去重，文案“参考来源 N 个”。同一来源的事实摘录/推断只算一个来源。AI推断和原创假设作为各自内容类型展示，不累加成外部来源数。无外部来源时显示“原创提案”，详情说明“未引用外部来源”；不能因此断言所有内容已验证。

### 原始内容与展示内容分开

原始记录保留。已知系统说明转换为清楚的中文含义，不向普通界面输出actual_work_hours、strategies等字段名；无可靠规则的说明保留含义和完整文本，不做可能改变风险性质的自动摘要。事实引用不改写、不裁成新的事实。

不新增数据库迁移或AI总结请求；可扩展只读接口的展示摘要及契约。批次上下文与来源摘要按当前可见选题集中读取，避免逐条额外请求和跨账号泄漏。列表不因每个条目的展示而请求全部详情。

本轮不接入历史内容、受众、实际工时或指标到选题模型，不声称只调整界面就提升了模型质量。那些数据链路另行定义工作范围。

## 6. 详情阅读与操作

复用CHANGE-019已有840px抽屉、固定标题/操作与单一正文滚动，不重做为多层弹窗。

阅读顺序：

1. 标题、状态、形式及必要过期提示；不堆叠评分/工时缺口。
2. 写作角度、写给谁/解决什么问题、阅读场景、为什么值得继续关注，保持完整正文。
3. 选题依据：原文摘录、AI推断、原创假设分组，提供真实来源链接及观察时间。
4. 使用前核对：本题具体假设、风险、无法归类的原始警告常显，不折叠到“高级信息”。
5. 本次生成参考了什么：默认折叠，包含批次共用资料范围与限制；不把这些限制当独立任务。
6. AI评分依据：默认折叠，显示服务端总分、六维理由与权重说明；去掉无意义的“.00”，保留实际小数，不重新计算分数；明确不是成功率或效果预测。
7. 制作时间：只有已有非空估计才显示为估计；未知时不再追加独立“待补”段落，批次说明已解释估时边界。
8. 决策记录：默认折叠，沿用真实历史。

底部仍以“采纳选题”为主要操作，保留确认步骤；拒绝留因、显式创建变体、409读取最新版本/保留输入与失败可重试保持。仅有效待采纳题可采纳/拒绝；过期提示引导重新生成或明确创建变体后核验，已采纳题过期保留原决策。缺项本身不新增采纳阻断规则。采纳只保存决策，不执行制作或发布。

## 7. 分三阶段实施

| 阶段 | 工作内容 | 退出判据 |
|---|---|---|
| 1. 整理展示数据 | 明确共用/本题分类和兜底；按批次读取说明；补齐去重来源计数与必要只读契约 | 单批/混批/分页/旧数据都能准确归属，不猜测全局缺失，无逐条详情请求 |
| 2. 完成界面分层 | 单列条目、默认状态与空态；集中生成说明；详情核验/评分/时间分层；中文文案 | 长“待补”不在列表出现，无重复工时，无内部字段名，事实风险仍可见，状态/操作保持 |
| 3. 回归及本地验收 | 数据分类/来源计数与接口范围测试，页面状态/分页/错误/响应竞态/键盘/宽度；构建类型、必要Docker与本地只读/数据保持 | 验收清单逐项通过并留证，再更新本地；规划与示意不当测试通过 |

顺序为1→2→3。若阶段1发现批次记录缺失，按历史兜底继续，不要求重新调用AI或批量重生成旧候选。本规划不估算为已完成工时，也不创建新的S任务或改69任务统计；实际开工时再重开相关稳定任务。

## 8. 验收清单

- 两条截图样本仍保持过期与原决策/内容；列表没有七项长段落、三次工时提醒或“3条引用”误计，实际各显示一个参考来源。
- 列表首要内容为标题和写作角度；完整关注理由、评分和资料局限不再抢占每条正文。
- 相同批次只解释一次共用限制；多个批次、混合账号、分页加载、历史变体及缺记录不能相互污染。
- 当前未传给生成的资料明确表述为“本次未参考”，不误写用户从未录入；没有无入口的强制补齐任务。
- 同源多条片段、只有推断、纯原创、无来源、空缺项、有未知警告均准确显示；未知风险不被吞掉。
- 采纳/拒绝/变体、过期、已采纳过期、409/普通失败、提交禁用/重复操作及输入保留与原业务一致。
- 1440/1280/768/390/320下无页面横溢出，长标题与无空格文本换行，主要触控入口至少44px；说明、评分、历史可键盘展开，关闭返回触发入口。
- 当前筛选与分页保持；加载/读取失败/空态正确，迟到响应不覆盖新筛选，不自动生成或发起其他付费请求。
- 只读接口权限/契约检查、构建类型与相关页面检查通过；涉及展示接口时补充对应集成验证。未变化领域不无理由重复整套测试。
- 本地更新前后业务数据和默认身份/私有配置保持，截图脱敏；未代用户采纳、拒绝、生成或删除任何实际选题。
