`agent-reach doctor --json`及`check-update`均返回命令不存在；OpenCLI不存在；`mcporter list --output json`没有配置Exa或小红书server。CUA初始化因Node runtime路径不存在失败。没有读取浏览器cookie或桌面应用认证文件。agent-reach的通用Jina读取微博返回Sina Visitor System；后续采用匿名公共HTTP读取做可达性诊断。

- 提供方/目标：微博官方公开[实时热搜页](https://s.weibo.com/top/summary)。官方客服将该地址列为热搜入口，[说明](https://kefu.weibo.com/faqdetail?id=21636)。
- 实际探测：HTTP200，但内容标题Sina Visitor System；Jina读取也只有访客系统页面，没有榜单条目。
- 成功字段：仅HTTP诊断、采集时间；榜单名称、排名、原文链接均未提取。没有当前真实热点响应样本。
- 登录与运行机器：可能需可用授权会话或提供方；未验证，不能仅凭200认定成功。
- 请求：本轮一次匿名直连、一次Jina；未做高频重试或绕过访问限制。
- 失败恢复：尚无可用连接，未实施真实会话失效/恢复、连续成功或配额试验。仅确认为访客门禁，恢复方案待提供方确定。
- 授权、费用、配额、数据保存范围：未提供。
- 结论：BLOCKED；需要可用读取条件或授权数据提供方，随后做真实成功及超时/限流/会话/字段变化恢复测试。

- 授权、服务提供方、费用、配额、保存范围：未提供。当前无可用OpenCLI/MCP后端。
- 失败恢复/连续成功：未运行；当前不能选择真实适配器。
- 结论：BLOCKED；需首先确认实际来源是榜单、话题信号还是供应商自建榜，再获取明确范围内的真实条目。推荐feed不能重新命名为官方热点榜。

## 统一后续验证顺序

确定提供方/授权范围 → 验证登录/能力 → 有界实际成功样本 → 连续多次读取 → 在可控环境测试超时/限流/会话失效/字段变化 → 确认成本、频率、保存与值班责任 → 关闭对应任务。模拟错误只验证错误处理，不替代真实成功证据。
