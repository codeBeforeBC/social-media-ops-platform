## 2. OpenCLI路径

参考[适配器源码](https://github.com/jackwener/opencli/blob/24136945847afbfad266c6c46a8cd335377f9112/clis/weibo/hot.js)及[微博命令文档](https://github.com/jackwener/opencli/blob/24136945847afbfad266c6c46a8cd335377f9112/docs/adapters/browser/weibo.md)。软件许可证Apache-2.0。

源码将命令声明为read、COOKIE策略：先导航微博，再在页面中fetch相对路径 `/ajax/statuses/hot_band`，携带浏览器会话，取 `data.band_list`，最多50条。输出rank/word/hot_value/category/label/url；不输出onboard_time。安装版1.8.8的hot.js与上述修订所读文件逐字节一致。

本轮仅在 `/tmp/yoyo-opencli-verify` 安装固定版本，使用 `--ignore-scripts`；Node24.14.1满足包的Node≥20.18.1要求。实际doctor确认daemon运行而extension未连接。因此当前缺口是Browser Bridge连接，未到验证账号登录态的步骤。没有读取Cookie数据库、安装浏览器扩展或执行发布/删除/点赞。

如采用OpenCLI，准备Chrome/Chromium＋官方Bridge，按文档完成微博登录，再运行：

```sh
opencli doctor
opencli weibo hot --limit 5 -f json
```

先取得真实命令输出，然后测试持续在线节点和会话恢复。网页请求匿名成功不表示可删去工具自身的浏览器依赖。此次探测启动的daemon已停止，没有留下本轮持续服务。

## 4. 对YOYO的推荐路线及字段

调整此前“优先TianAPI”的研究建议：**在当前本地环境先验证 `hot_band` 的有界HTTP读取适配器，可减少浏览器持续在线和商业服务依赖；OpenCLI留作桌面备选，TianAPI留作有明确服务范围的供应商备选。** 正式部署环境仍要复测，不能假定本机匿名能力在服务器同样成立。

| 业务字段 | 建议映射 | 不能混用 |
|---|---|---|
| source_type | 微博网页热搜数据，实际提供方为微博网页端 | 不称为已授权开放平台API |
| title | word，缺失时拒绝条目或标解析异常 | 不生成“热搜1”冒充标题 |
| source_url / 去重键 | 从word_scheme/word构造编码正确的搜索URL；保存规范URL与内容指纹 | 不用列表序号或排名作为稳定external_id |
| rank | realpos原值；无值为null，列表位置独立保存 | 不把位置回填成官方排名 |
| hot_value | num原值，数值类型校验；缺失为null | 不把热度当阅读量、点赞或涨粉 |
| captured_at | 本次UTC采集时间 | 不冒充发布时间 |
| onboard_time | 原字段及转换后的UTC值，按“上榜时间”单独保存，业务语义还需确认 | 不填published_at；无该字段保留null |
| published_at | null | 热搜话题不等于一篇微博正文 |
| category / label | 原可见值，区分空字符串与字段缺失 | 不补造分类 |

建议沿用09:00/16:00、单源单并发、每次最多50条初始预算；这是本项目建议频率，不是微博公布的允许配额。两次请求成功不证明无限调用或长期保存范围。
