# 小红书媒体类型识别修复

日期：2026-10-07（Asia/Shanghai）。关联 BUG-002、S0-02/03、NAV-02/03。使用用户指定的“yoyo运营”/`zrcmcu2d`，OpenCLI 1.8.8、Bridge 1.0.24、Chrome 154.0.8037.99。

**BUG-002已修复：S0验证脚本把图文笔记中的 Live Photo 播放器误认成视频笔记。** 修正主媒体识别后，7个DOM回归案例、9个守卫测试全部通过，原完整真实读取矩阵也通过，包括此前失败的同一篇笔记。此结论关闭脚本误识别缺陷，不关闭来源跨日、真实登录恢复或产品集成验收。

## 根因与修正

原失败笔记为 `69ea27ca0000000019025c03`，标题“《旅行》绝对是我的北影节最佳!”。诊断时“笔记类型”活动选项是图文，搜索URL类型为51；立即读取与等待3秒后的前5条卡片ID一致。详情的图片轮播 `.note-slider .img-container` 中同时存在图片与 `.live-photo-contain` / `.live-video-wrapper` 下的 `<video>`，用于播放动态照片。

原脚本只要详情面板内存在 `<video>` 就返回video，因此错误拒绝了该图文结果。本次证据支持脚本识别错误，没有证明上游图文筛选错误；也不能据此推断所有筛选场景均可靠。

- [主媒体识别器](../../../tools/s0/xhs-detail-media.mjs)：仅检查 `.media-container`。图片轮播中的Live Photo仍返回image，并单独返回 `has_live_photo=true`；独立视频返回video；结构冲突或未加载返回unknown。
- [真实读取脚本](../../../tools/s0/probe-xhs-navigation.mjs)：复用同一识别器，等待已知媒体类型及稳定详情字段；仍校验目标ID、登录/安全提示及筛选类型，未增加盲目重试。
- [DOM回归脚本](../../../tools/s0/verify-xhs-detail-media.mjs)：在Chrome中用DOMParser构造脱离当前页面的测试节点，不修改真实页面。覆盖Live Photo、普通图文、独立视频、头像、推荐区视频、冲突结构与未加载状态。
