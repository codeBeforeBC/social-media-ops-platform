# S0 来源收口验收方案

编制：2026-10-07（Asia/Shanghai）。关联 S0-01–03、BUG-001、IN-01。本文是拟执行的操作和验收标准，不是新的成功证据；实际状态只在[开发进度](../../tracking/开发进度.md)维护。

依据：[来源设计](../../yoyo-workbench-v1.0/08-自动采集与外部依赖.md)、[微博实测](微博开源读取验证.md)、[小红书实测](小红书授权浏览器验证.md)。三天、六轮及下述样本数量是本次建议的 S0 最小观察方案，原设计没有规定这些数量，也不能据此声称长期稳定。

## 1. 导航诊断与适配固化

目标：使选定的读取路径能够从关键词自动取得列表和详情，并解释、保留原生命令失败的原因与影响。

### NAV-01 定位拒绝发生在哪一层

1. 固定本机、Chrome“yoyo运营”/`zrcmcu2d`、OpenCLI 1.8.8、Bridge 1.0.24，先检查连接和站点登录状态。所有命令显式指定 profile。
2. 先读 CLI/Bridge 对应导航代码，核对 URL 构造、路径校验、标签页租约、重定向和错误返回。为原生 note 及“情绪价值”查询分别记录一次失败链路，不把它们直接认定为同一原因。
3. 只保存脱敏的命令类型、域名/路径、耗时、发生层、最终页面类型及错误；签名参数和 Cookie 不进入仓库。现有证据不能确定 `Navigation rejected` 来自 Bridge 还是站点，报告必须保留这个不确定性。
4. 工具错误按诊断结果修复 URL/租约/调用方式。确认为登录、验证码或站点访问拒绝时，停止相应来源并转人工恢复；不以反复请求或换账号定位。

通过：失败能够复现或得到足够的层级证据；选定路径的修复及残余限制有记录。无法定位的拒绝保持未关闭，不把它伪装成正常空结果。

### NAV-02 将可用读取路径保存为可复现代码

候选方案是固定版本的 CLI 搜索，加页面内卡片点击读取详情。原生 note 命令不必成为产品依赖，但采用替代方式须验证相同需求覆盖，并明确记录原生命令仍不可用。

2026-10-07导航验证增加了保留debugger连接后的签名导航候选路径，详见[实测报告](小红书导航问题验证.md)；导航已成功；随后[媒体识别修复](小红书媒体类型识别修复.md)关闭BUG-002，原完整读取矩阵通过。来源跨日/恢复及其余范围仍待验收。下述卡片点击保留为已取得证据的候选方式，不能将两种方式的验证范围混写。

- 将[可见性补丁](../../../tools/s0/opencli-xhs-visibility.patch)纳入有版本/原文件哈希校验的安装流程；文件不匹配时停止应用，避免依赖更新后打错补丁。
- 把“搜索 → 按笔记 ID 找到实际卡片 → 点击 → 等待目标详情加载 → 校验笔记 ID → 提取 → 返回列表”保存为脚本。不能靠固定第一个卡片或单纯睡眠三秒判断成功。
- 设置总超时、读取数量和滚动上限；详情等待使用目标 ID、加载状态和页面字段条件。超时、登录墙、页面变化、缺字段分别留下结果，不写假正文、假日期或零互动。
- 签名链接仅用于当前读取上下文；保存稳定 ID、无签名规范 URL、采集时间、原始日期及互动原值。缺少可信发布时间为 null，ID 推算日期另存。

通过：从新的临时安装目录能够按说明复现搜索和详情；实现不依赖本轮 /tmp 中手改文件或浏览器旧页面。

### NAV-03 回归矩阵

- 导航回归关键词：旅行、潮玩、情绪价值，每词最多 5 条；另验证综合/最新排序及一次有界滚动。
- 至少 3 篇不同笔记详情，其中覆盖公开图文与视频笔记的文字/可见字段；不下载视频。逐条核对目标 ID、标题、正文或缺失原因、作者标识、原始日期、可见互动。
- 加入受控的超时、字段变化、登录墙、拒绝、过期链接或内容删除案例，检查不会误判成功。真实空结果与读取失败分开记录。
- 这三个词是故障回归样本；最终报告另列旅行/IP/潮玩/情绪及参考账号入口的实际支持情况，不能把未测试能力声明为支持。

通过：选定路径覆盖导航回归矩阵且没有未解释的拒绝、错读或假成功。若“情绪价值”等必要范围仍不可读，维持待验证；来源或覆盖范围变更另行记录，不能默默去掉失败样本。

BUG-001 只有在筛选问题可复现修复、必要导航能力经选定路径验证、原生命令残余限制与根因/影响明确后才能收口。切换路径本身不等于上游缺陷已修复。

## 2. 跨日稳定性

### DAY-01 三天、六个观察窗口

导航路径固化后，在选定运行节点连续三个观察日，每天 09:00/16:00（Asia/Shanghai）各观察一轮。开始日期依真实执行填写；没有创建定时任务，不承诺自动运行。已有同日结果作为前期证据，不补写成跨日窗口。

每轮建议：微博主路径 hot_band 最多 50 条；小红书上述三个词各最多 5 条，再读合计 2 篇详情。同源单并发、逐项执行，数量与间隔须服从来源实际限制；09/16 是建议窗口，不是已证明被允许的请求频率。

每轮记录 run_id、计划/实际时间、机器、profile、依赖/适配器版本、健康状态、总耗时、唯一 ID 数、字段缺失、错误及脱敏证据摘要。榜单/搜索结果不必每轮变化，不能以“内容变化”作为成功硬条件。

验收：

- 六个窗口全部有执行记录，正常窗口无需重新登录或手工提供链接，列表与详情能完成且字段语义正确。
- 缺跑、超时、拒绝、机器离线如实记录；计划窗口缺跑不算成功。修复后补观察日，直到取得三个完整的连续观察日；历史失败保留。
- 包含至少一次本地连接/进程重启后的读取；现有 daemon 重启证据可复用，版本或节点变化后再针对变化复验。
- 验证报告明确这是短期可用性证据，不是生产 SLA。迁移至其他机器须重验浏览器、网络和会话条件，不能把本机结果等同于服务器验收。

运行机器睡眠、Chrome/扩展退出会影响浏览器读取。机器保持在线的责任和窗口必须明确；S0 不要求全天候生产采集系统已经实现。

## 3. 会话恢复

### REC-01 受控失败分类

先用本地受控输入验证分类，再做正常来源恢复验证，避免为了测试去制造平台限流/验证码。

| 现象 | 判定依据 | 恢复动作 |
|---|---|---|
| Bridge/daemon 断开 | doctor/连接状态；站点登录仍可用 | 重启本地连接，重连指定 profile，验证一次搜索和详情 |
| 登录失效 | 实际登录墙或明确认证错误 | 暂停来源，负责人在 yoyo运营 中重新登录，再验证 |
| 签名链接过期/笔记不可访问 | 保留原始错误，重新取得页面入口后判断；不能仅靠错误猜测 | 在正常会话中重新搜索获取当前入口；已删除内容保留不可访问状态，不循环请求旧链接 |
| 验证码/站点拒绝/限流 | 实际提示或响应；未知导航拒绝仍保留未知原因 | 暂停对应来源，由负责人处理；遵从明确的恢复时间/条件 |
| DOM/字段结构变化 | 登录正常，但目标字段/页面结构不符合预期 | 记录 SOURCE_CHANGED，修复适配器并回归后恢复 |

通过：受控结果均能分类，成功记录不被覆盖成空数据；暂停条件与人工动作明确。未知错误保留原始错误和发生层，不硬映射成账号过期。

### REC-02 真实人工重新登录演练

本地 daemon 重启已验证，但不等于站点账号过期恢复。本项需要一次真实的人工重新登录链路；可在自然失效后执行，或由账号负责人选择方便的时间手动退出再登录，不在开发过程中擅自退出账号。

1. 记录登录失效被识别，读取停止，并列出人工恢复动作。
2. 负责人在同一“yoyo运营”档案完成登录；不向开发者交密码或 Cookie。
3. 检查 Bridge 和页面登录状态；通过新的搜索取得当前卡片/链接，不重复使用上次保存的签名链接。
4. 进行一次小规模列表＋详情读取，校验 ID/字段；成功才解除暂停。仍失败则保留暂停及错误证据。

通过：失效识别、人工登录、验证成功、解除暂停四步均有脱敏时间记录。受控登录墙案例可以验证识别逻辑，但不能写成真实重新登录成功。

## 4. 最少外部输入与关闭条件

### INPUT-01 确认运行约定

已收到：Chrome 档案、profile ID、扩展和登录。无需重复提供。

尚需明确：

- S0 的观察节点是否使用当前 Mac，以及上述窗口能否保持机器联网、Chrome 与扩展可用。
- 账号登录失效由谁处理，以及真实重新登录演练的方便时间。
- 读取/保存边界及来源允许的频率：本轮建议继续公开搜索和公开详情，只保存必要文本/摘要、公开标识、日期与可见互动；具体字段及保留期限写入来源报告。当前账号登录不自动证明其他 API、后台或保存权限。

NAV-01–03、DAY-01、REC-01–02、INPUT-01 是原任务下的验收检查点，不新增开发叶子任务或改变 64 项分母。结果回填到[任务工作记录](../../tracking/开发进度.md)。

S0-01–03 仅在各自真实读取、来源类型/字段、节点/频率/范围、跨日及适用的失败恢复证据齐备后标 DONE。微博采用匿名 HTTP 路径时不需要小红书登录恢复，但仍需自己的受控错误与跨日报告。

S0 阶段还包含媒体、后台样本、AI/OCR 服务与预算，来源收口不能替代 S0-04–06。产品级持久采集任务、页面健康状态、定时调度、通知与自动恢复在 S1/S3 实现，T03/T04 届时验收；S0 探测通过不直接把它们标 PASS。
