## 页面与接口

- 添加账号可选择已连接的浏览器context ID，并“保存账号”或“保存并验证”。保存和验证受理各有反馈；验证提交失败保留已经登记的账号，可在详情重试，不重复创建。
- 详情分别显示公开身份、当前登录身份、平台返回昵称/展示号、实际观察时间、可读能力、人工管理确认及验证历史。登录错号不自动换登记身份，也不声称后台可读；当前实现未读取后台指标，能力保持unknown。
- 队列/执行阶段自动读真实Job状态；刷新/关闭页面不丢任务，读取故障可恢复，终态停止活动轮询。验证有同绑定60秒冷却，活动任务复用；重新验证增加历史记录，通用Job重试不覆盖旧证据。
- 换档案增加独立绑定版本并使旧确认失效；改备注/时区保留身份观察。并发刷新保留未保存的档案选择。人工确认要求显式声明、最新当前绑定公开匹配、24小时内观察与expected_version，不证明平台所有权或替代授权。
- 新接口为档案发现、验证创建/分页/详情及管理确认；GET账号附最新尝试/历史匹配/时效摘要。工作区、账号及确认外键范围均在服务端校验，客户端不能提交“已验证”字段。

实现：[验证领域与任务](../../../../packages/domain/src/account-verifications.ts)、[页面核验区](../../../../apps/web/src/account-verification.tsx)、[040迁移](../../../../packages/db/migrations/040-account-verification.sql)、[固定浏览器动作](../../../../tools/s3/xhs-account-verify.mjs)、[桥接](../../../../tools/s3/source-bridge.mjs)。已有general池承载验证，和来源采集共享context锁；不增加原架构没有的执行池。

## 真实读取与失败边界

真实链路运行于独立 `yoyo_change020_real_test`，使用当前授权会话观察出的真实身份作为样本，固定OpenCLI 1.8.8。平台访问只读公开主页和当前登录身份字段；不读取Cookie、密码、完整用户状态、后台指标，不发布或调用模型。

故障恢复试验把该隔离进程的桥接URL临时指向未监听端口，得到实际BROWSER_UNAVAILABLE终态；恢复地址后再次读取真实身份成功，保留三条不可变尝试。未在真实账号强制退出、触发验证码或制造平台限流；相应分支由受控适配器测试覆盖。控制测试与真实成功明确分开，不把受控结果当成平台故障实测。

原已登记账号仍有IN-10：内部ID格式不符合要求，也不等于此前会话样本。升级未替换/认证该记录，没有把隔离验收的人工声明写到生产账号。真实目标归属仍须用户核对；错误ID不能通过验证入口，内部ID不能普通编辑或静默迁移历史数据。

## 备份、升级与运行服务

[受限同点备份](backup.json)保存database.dump、state.tar、objects.tar及镜像清单，并检查全部SHA256；原件只在私有.local。API/worker/media/scheduler的旧运行文件系统已保留为本机回滚镜像，并核对旧编译文件hash。旧镜像清单丢失时从正在运行的容器导出/导入，未冒充原image ID仍可拉取。

本轮发现BUG-038：运行容器的根文件系统仍在，但旧浮动标签镜像清单已不存在，直接按旧ID运行tar会失败。[备份脚本](../../../../tools/s9/backup.sh)改用可用本地Compose镜像读取卷；两个镜像均不可用时在停止服务前退出。[两项行为回归](backup-unit.log)与实际备份通过。首次[快照列校验失败](backup-first.log)保留；旧镜像清单失败的完整首轮文件未保留，已做[只读复查](backup-missing-manifest.log)，不将该失败或复查算成备份完成。

升级步骤为受限备份→真实副本恢复/迁移→配置私有桥接令牌文件→停止应用写入→执行040→更新API/worker/media/scheduler。数据库默认身份、原数据投影、原AI私有配置与来源定时开关保持；原始字段投影用于比较，避免把新增字段的默认值误报成旧数据修改。验证证据新增表是预期结构变更。

宿主桥接使用固定RPC、已连接context ID和私有令牌文件，监听59025供本机Docker访问；当前宿主进程已启动。API/worker从`/state/source-bridge-token`读取0600文件，Compose只保存文件引用，真实令牌不写仓库或.env。宿主重启或该进程退出后，在项目目录运行：
