# 浏览器连接恢复

适用于当前YOYO本地实例与项目固定的OpenCLI1.8.8。当前连接链路为：工作台 → 宿主source-bridge（59025）→ OpenCLI daemon（19825）→ Chrome里的OpenCLI插件。工作台运行正常，不代表两个宿主进程一直运行；关机或进程退出后可能需要重新启动。

## 先从页面恢复

1. 打开原来登录小红书的Chrome用户配置，保持Chrome运行。
2. 在Chrome的扩展程序管理页检查 **OpenCLI / Browser Bridge** 插件已启用。不要在工作台粘贴密码或Cookie。
3. 回到YOYO，打开“添加来源”，选择一种小红书来源，在“采集使用的浏览器”处点击“刷新列表”。出现可选浏览器，表示连接恢复；它仍不证明平台登录或真实采集成功。
4. 如需采集，在该Chrome中确认小红书已登录；回到来源列表，由用户按实际需要点击“立即采集”，通过运行记录判断采集结果。账号身份验证使用运营账号自己的验证入口。

## 页面仍读取失败时

在项目目录 `/Users/junlong/projects/social-mdeida-ops-platform` 打开终端；当前环境未全局安装opencli，请使用项目固定的本地入口。

检查daemon：

```sh
node .local/providers/opencli/node_modules/@jackwener/opencli/dist/src/main.js daemon status
```

若未运行或插件持续无法连接，等现有采集/核验任务结束后重启daemon；Chrome已打开且插件启用时会尝试自动重连：

```sh
node .local/providers/opencli/node_modules/@jackwener/opencli/dist/src/main.js daemon restart
```

检查YOYO的宿主桥接是否监听：

```sh
lsof -nP -iTCP:59025 -sTCP:LISTEN
```

只有端口没有监听时，启动现有桥接：

```sh
node tools/s3/source-bridge.mjs
```

该命令使用本地已有令牌文件，不需要复制令牌。前台运行时需保留此终端；如果端口已被占用，不要重复启动或随意结束进程。保持当前的回环监听和鉴权，不改成无鉴权或对外监听。再回到页面刷新浏览器列表。

若工作台本身无法打开，先检查Docker及本地实例；这与插件连接是不同层的问题。若daemon已运行但没有浏览器档案，优先检查打开的Chrome用户配置、插件启用状态，再检查插件显示的错误；无需先重新添加运营账号或来源。现有记录不会因刷新浏览器连接而自动重新采集。

本指南没有配置开机自启，也没有升级OpenCLI/插件。2026-10-31的实际复查与恢复证据见[连接检查](../evidence/change034/README.md)，任务状态只见[开发进度](../tracking/开发进度.md)。
