## 目标与选择

别人 clone 项目后，通过少量配置即可本地使用，尽量减少单独安装软件。采用完整 Docker Compose 作为普通使用者默认启动方式；开发者保留原生 Node/pnpm 启动入口，可连接 Compose 提供的数据库和存储，也可连接自行准备的兼容服务。

普通使用者需要 Git 和支持 Compose 的 Docker 运行环境；Mac/Windows 文档以 Docker Desktop 为默认路径，Linux 可使用 Docker Engine 与 Compose 插件。Node、pnpm、PostgreSQL、FFmpeg/ffprobe、PDF 处理工具及存储服务封装在镜像中，不要求普通使用者单独安装。首次启动仍需网络下载镜像，并需要足够磁盘、内存及可用端口；最低要求在 S9 实测后记录。

本决策补充并调整 [ADR-001](ADR-001-技术与运行环境.md) 的运行与交付方式，保留 PostgreSQL、S3 兼容私有存储、持久 Job/Outbox、独立提醒处理和媒体隔离设计。原生运行可以减少 Docker 依赖，但增加逐项安装与版本维护；云服务减少本机服务安装，却增加账号、网络和费用配置，因此均不作为默认使用入口。

## 目标使用流程

以下为完整交付目标；当前S1源码启动、初始化凭据获取与功能范围见 [项目README](../../README.md)。发布时应提供真实仓库地址及预构建镜像。

```sh
git clone <仓库地址>
cd social-mdeida-ops-platform
cp .env.example .env
docker compose up -d
```

启动后通过本地网页完成首次管理员设置。默认仅暴露本机网页入口，不公开数据库、存储管理端口或未初始化的管理界面；开发调试端口通过可选配置开启。首次设置需实例专属的一次性凭据验证，管理员创建采用事务与唯一约束，成功后关闭初始化入口，不提供公共默认密码或开放注册。

## 配置与运行约定

- Compose 管理网页/API、独立 worker/scheduler/提醒处理、PostgreSQL 和私有存储；媒体执行保留权限、时间及资源限制，不能仅因进入容器就视为安全隔离完成。
- `.env.example` 提供无密钥默认配置，仅在需要时修改端口、数据位置和外部服务参数。内部密钥/服务凭据首次自动生成，保存到受限持久位置；重复启动不重置，不把密钥写入仓库、镜像或普通日志。S1初始化入口及获取凭据的管理命令见项目README。
- 健康检查确认数据库和存储可用后，执行串行、可重复运行的迁移和存储初始化，再启动应用；失败时显示可诊断信息并停止依赖服务就绪，不能假报启动成功。升级迁移沿用兼容性和备份要求。
- 数据库、原件/预览与内部凭据使用持久卷；普通停止、重启、重建容器及兼容升级保留数据。持久卷不代替备份，提供备份/恢复入口；删除卷或清空数据不进入普通启动、停止和升级流程。
- 开发原生入口与 Compose 共用契约、迁移和配置名称；开发/测试/生产数据、凭据与任务空间分开，测试种子不写入普通使用实例。
- 发布提供版本固定的预构建镜像，使用者默认拉取运行；源码构建作为开发/备用路径。发布镜像至少覆盖 linux/amd64、linux/arm64 并逐架构验证原生依赖；版本标签及 digest 可追溯，不依赖浮动 latest。镜像仓库与发布权限在发布前落实，本次未授权发布。

## 外部能力边界

基础人工操作不要求预先配置 AI/OCR 或来源账号；未配置能力明确显示未启用，禁止后台自动付费调用或用 demo 冒充真实输入。对应制作、审核、资产管理功能按原阶段实现，本决策不表示 S1 已提供完整业务系统。

AI/OCR 需要用户配置可用服务、数据处理范围和预算。来源需要独立授权；当前小红书路径依赖宿主机浏览器、Bridge 和人工登录，Compose 不自动搬运浏览器登录态，也不内置 cookie。S3 需验证容器到授权执行器的连通、认证、暂停/重连及配置流程，并披露浏览器关闭或宿主机休眠时的能力限制。生产来源须采用符合持续运行要求的执行节点，保留原上线门禁。
