# ADR-001 技术与运行环境

日期：2026-10-06。状态：开发基线已采用；生产服务、预算和域名未决项见下表。关联 S0-07。选择基于单工作区、单账号、约5人协作及完整R01–R15。

## 采用的结构

TypeScript 单仓库，pnpm workspace；React + Vite 前端；NestJS 模块化 API；PostgreSQL；Prisma 数据访问与显式 SQL 约束/迁移；S3 兼容私有对象存储。API、worker、scheduler 为独立进程，共享领域模块。数据库 Job、Outbox、租约支撑持久任务，首版不增加 Redis 或消息中间件。提醒独立进程/领取池，媒体隔离进程；AI、OCR、来源由适配器接入。

原2026-10-06方案：开发阶段 Docker Compose 运行 PostgreSQL 和本地 S3 兼容存储；Linux 容器是部署目标，生产数据库/存储可以替换为托管服务。2026-10-07用户确认补充：普通使用者采用完整 Compose 一键启动，开发者保留原生启动入口；镜像封装应用、数据库、存储与媒体工具，首次设置、持久化、预构建镜像及验收归属见 [ADR-003](ADR-003-本地一键启动与交付方式.md)。S1当期实现与验证见 [证据](../evidence/s1/README.md)，完整交付按后续阶段继续。Mac 上的 Apple Vision 仅为本轮OCR样本验证，不纳入Linux部署承诺。

数据库关键约束、行锁和事务必须显式实现；ORM不是并发、跨账号或唯一性保障的替代。前端查询缓存不决定业务状态；AI仅返回提案，业务写入由领域命令执行。

## 版本与本机核验

以下为2026-10-06冻结时的环境盘点；当前运行验收以S1证据和任务台账为准。

本机实际 Node 24.14.1、pnpm 10.33.0。FFmpeg、ffprobe、Poppler、Swift可用。Docker客户端存在，但daemon socket不存在，容器尚不能启动；psql不在PATH。

采用 Node 24 LTS、pnpm 10、React 19、Vite 8、NestJS 12、PostgreSQL 17。Prisma CLI/client采用同一稳定7.x版本，不使用注册表latest指向的8.x RC；TypeScript先采用5.x稳定线，S1安装时检查Nest/Prisma/Vite的兼容要求并锁精确版本。

本轮registry观察和engine记录见 [package-registry-probe.json](../evidence/s0/package-registry-probe.json)，只证明包元数据存在，不代表已经安装或集成成功。精确版本、镜像digest和锁文件在S1-01建立，不以最新tag自动升级生产。Nest官方文档指出CLI生成器需要Node24.15+，本机24.14.1未满足；S1应使用项目指定的兼容Node版本，或手工搭建工程，不能直接假设本机可运行新CLI。[NestJS prerequisites](https://docs.nestjs.com/first-steps)。Node24的LTS状态参考[官方发布计划](https://github.com/nodejs/Release)，PostgreSQL17的支持周期参考[官方版本政策](https://www.postgresql.org/support/versioning/)；不依赖网页显示的“最新补丁号”做环境锁定。

## 登录协议

首版默认内部邀请账号，以邮箱作为登录标识，账号密码与第三方社交平台凭据完全分开。不开放公开注册；管理员通过受限初始化/成员管理流程创建成员，实际初始管理员信息在S1配置。密码使用Argon2id，随机盐，参数在目标机器测量后记录；不发送任何平台密码给模型。

- `GET /api/v1/auth/csrf`：匿名短期会话或现有会话生成CSRF令牌。
- `POST /api/v1/auth/login`：校验Origin、CSRF和登录限流；验证内部凭据后轮换会话ID，避免会话固定。
- 服务端保存高熵随机会话令牌的哈希；Cookie使用HttpOnly、SameSite=Lax、生产Secure。开发localhost的Secure例外仅限开发环境。
- 所有写操作校验Origin和CSRF。会话绝对有效期建议12小时、闲置期建议2小时，可配置；停用成员或角色更新即时检查数据库授权。
- `GET /auth/session`和`GET /me`返回身份、角色和过期时间；过期返回401，不能继续静默写入。
- `POST /auth/logout`撤销服务端会话，清理Cookie。授权下载短期签名不写日志；不得将会话令牌放localStorage。
- 企业OIDC/SSO将来接入时复用内部Membership和会话，不改变角色来源。若用户已指定现有SSO，按最新要求替换此默认决策。

上述是协议决策，认证尚未实现或安全验收。

## 运行默认值

时区Asia/Shanghai，持久化UTC；文件上限2GiB（2147483648字节）、上传并发2；初始分片8MiB。来源计划09:00/16:00但未验证连接保持禁用；每源单并发、最多50条候选。AI并发2、媒体2、提醒独立小池；提醒扫描5秒，前1天/1小时/到点站内通知。签名下载建议5分钟。运行日志90天、失败分片7天。以上可配置且需对应阶段实测。

AI/OCR预算默认未配置，生产调用默认关闭；测试开关亦需明确任务/每日金额，不自动试用现有桌面账户的登录额度或凭据。RPO24小时/RTO4小时是验收目标，不是本轮实测。
