## 状态与更新规则

| 状态 | 含义 | 必须记录 |
|---|---|---|
| TODO 待开始 | 未开工，或等待正常前置依赖 | 任务范围、依赖、完成判据 |
| DOING 进行中 | 当前正在实现或验证 | 负责人、开始日期、实际进展、下一步 |
| VERIFY 待验证 | 已有实现/报告，尚未通过全部验收 | 产物、已执行检查、缺失验证 |
| BLOCKED 阻塞 | 已确认缺外部输入或存在不能继续的问题 | 原因、所需输入、解除条件、可继续的替代任务 |
| DONE 已完成 | 完成判据全部满足且证据可追溯 | 完成日期、代码/文档位置、测试命令或人工验收记录及结果 |
| CANCELLED 已取消 | 经明确范围变更不再实施 | 变更依据、原因、需求/验收影响；不能用取消掩盖P0缺口 |

- 建议单一开发者同时最多一项 DOING；父阶段完成需其所有未取消子任务 DONE，且相应验收门禁关闭。
- 部分完成仍为 DOING/VERIFY，在工作记录中列已做与剩余，不凭主观填“80%”。发现回归可将 DONE 重新打开，保留旧证据和重开原因。
- 表中依赖为完整完成所需的硬前置；可提前探索/使用明确标注的模拟实现，但不能在真实验证依赖未完成时标 DONE。一个依赖阻塞不代表整个阶段停工。
- 更新时改任务行状态及证据列，补充任务工作记录，追加日志，再刷新当前快照和下一步。不要只更新聊天或开发日志。
- 任务编号永久保留；拆分时新增如 S3-02a，父任务仅作汇总并移出叶子计数，记录分母变化。新增缺陷用 BUG-001 起，纳入同一状态表和发布门禁。
- 负责人默认“未分配”，验收人默认“未指定”；开工时在工作记录赋值。没有明确排期日期，不填假截止时间。
