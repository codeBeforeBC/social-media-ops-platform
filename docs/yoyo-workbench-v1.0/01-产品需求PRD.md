# 01 产品需求 PRD

版本 v1.0｜2026-10-06｜需求编号为跨文档引用的稳定标识。

## 1. 背景与成功定义

用户是设计师，拥有 YOYO 形象规范与 2D、3D 等资产，希望 AI 承担成熟运营的研究、选题、制作组织、提醒与复盘工作，自己主要负责视觉和视频创作及内部确认。

主目标：账号获得持续且与内容定位相符的关注。北极星观察为账号周净增粉，辅以 28 日趋势、可用的单篇关注效率及内容生产投入。没有完整后台数据前，不设保证涨粉人数、不声称已经找到增长瓶颈。软件是否验收与涨粉是否达标分开。

产品使用者：同一内部团队的负责人、设计/制作人员、内部审核人员、运营人员；允许一人兼任。首版按一个工作区、一个小红书账号实现，多账号切换不是首版需求，但所有数据保留 account_id 以避免混数。

## 2. 业务闭环

配置账号和规范 → 导入自有资产 → 自动采集外部线索 → AI 筛选并推荐 → 人采纳 → 生成内容制作单 → 图文/视频制作 → 内部审核 → 人工发布登记 → 采集/导入结果 → AI 复盘 → 人确认下一轮策略。

活动帖增加并行链路：填写活动规则、参与截止、开奖时间 → 日历和待办提醒 → 人处理开奖 → 人登记公布结果。

推荐定位：陪你把旅行里的小心情，收藏成看得见的故事。首轮栏目为旅行情绪、小出走灵感、海螺来信，均为可编辑运营提案，不覆盖官方核心身份与人格，也不预设受众年龄和性别。

## 4. 功能细节与业务约束

自动采集的目的是形成可用选题，不是堆积原始信息。建议默认每天两次刷新，周初最多推荐 6 个候选供人选 3 个；次数、产能和栏目比例可配置。没有合适热点则推荐带标签的常青原创题，并明确热点采集状态。

内容制作单由 AI 生成、用户编辑。接受选题不代表接受全部生成文案；重新生成先形成新草稿，不覆盖人工修改。不得伪造用户来信、品牌活动、价格或旅行经历。

设计师实际使用外部设计和剪辑工具完成作品。首版提供管理、分镜、播放和归档，不承诺在线完整剪辑、模型建模或自动视频生产。

内部审核检查画面/IP、事实文案、文件顺序、视频声音与封面、相关素材使用条件。不增加独立品牌部门审批；规范文档作为制作依据而不是外部审批流程引擎。

发布包下载后仍为待发布。实际发布必须登记平台笔记 ID/完整链接、实际时间、内容版本及活动/投放标记。外部编辑、删除或重发分别记录。

## 5. 内容策略与品牌事实

官方手册 06/2026：携程旅行精灵、温暖向导、好奇乐观的旅行搭子；起源为海洋珊瑚丛，海螺收藏故事。形象蓝白配色、中央卷发、拟人脸、星光眼神、柔和 W 嘴型、海豚特征、身体比例不得任意重构。正式标准主色 #319AFF，辅助 #2582E6；肤色 #FFEAE0、腮红 #FFC6BA。完整手册为依据，界面中性色为 UI 提案。

官方规范与社交运营提案分层保存。提案经内部负责人确认才进入生效策略；不因 AI 一次生成或单篇数据好就永久改变角色。图库通过归属和版本区分同名 IP。

## 6. 非目标与体验要求

不做全网无限采集、绕过登录限制、自动评论私信、自动领奖或抽奖、粉丝个人信息库。首版不把“只开放网页时才轮询”当作可靠开奖提醒。

界面中文优先；主要操作应在两级页面内到达。只问用户无法从账号、选题和素材继承的信息。数据不足解释缺什么并提供入口，不生成假图表。

## 7. 业务评估

试运行先观察内容完成率、从采纳到成品的用时、素材复用、漏提醒次数、数据完整性；随后比较分组内容表现。记录制作实际工时，避免只优化发帖数量。无对照或归因时，增长结论只能作为观察和假设。

关键业务事件：采集完成、候选被采纳/驳回、制作单生成、内部审核通过/退回、实际发布、数据确认、周报行动采纳、开奖完成与公布。事件指标不携带完整私密文案、凭据或用户个人明细。
