# 03 业务状态与权限

v1.0｜2026-10-06。此文件是状态枚举的唯一基线；页面可显示更友好的中文，但不得另造互相冲突的状态。

## 1. 成员权限

| 能力 | 管理员 | 编辑/制作 | 内部审核 | 运营 | 只读 |
|---|---|---|---|---|---|
| 查看授权工作区内容 | 是 | 是 | 是 | 是 | 是 |
| 配置成员、数据源、密钥引用 | 是 | 否 | 否 | 否 | 否 |
| 编辑规范与资产、制作单 | 是 | 是 | 否 | 选题及发布文案 | 否 |
| 确认规范/素材可用、审核内容 | 是 | 否 | 是 | 否 | 否 |
| 采纳选题、调整排期 | 是 | 本人任务 | 否 | 是 | 否 |
| 登记发布、处理开奖 | 是 | 否 | 否 | 是 | 否 |
| 导入数据、采纳复盘策略 | 是 | 否 | 否 | 是 | 否 |
| 下载原文件 | 是 | 是 | 是 | 是 | 仅预览 |

允许同一成员兼任多个角色。首次内部小团队可由管理员承担所有角色；不是自动跳过确认。所有检查在服务端执行，隐藏按钮不足以实现权限。后台任务使用受限服务身份，AI 没有批准、发帖、公布结果或改成员权限的能力。

## 2. 内容与内容版本

内容业务状态：draft 草稿、in_production 制作中、in_review 内部审核中、ready_to_publish 待发布、published 已发布、cancelled 已取消。复盘状态单独记录，不将已发布内容改成“未发布的待复盘”。

| 动作 | 允许起点 | 结果/守卫 |
|---|---|---|
| 采纳选题/新建 | 无 | 建立 draft 和首个草稿版本；重复请求复用同一结果 |
| 开始制作 | draft | in_production；保存负责人和初始估时 |
| 提交内部审核 | draft/in_production | 文件已就绪、必填项完成、引用可用；冻结版本并创建审核请求，进入 in_review |
| 撤回/退回 | in_review | 回到 in_production；记录意见；旧审核请求关闭 |
| 通过 | in_review | 审核者确认当前待审版本；进入 ready_to_publish，保存 approved_revision_id |
| 修改发布载荷 | ready_to_publish | 新版本、回到 in_production；旧确认保留但不适用于新版本 |
| 登记实际发布 | ready_to_publish | 必须关联批准版本、真实平台 ID 与时间；生成发布记录，进入 published |
| 暂存发布信息 | ready_to_publish | 缺 ID/链接则仅产生待核对草稿，保持 ready_to_publish、不计入数据 |
| 已发布后修改 | published | 保留既有发布版本；派生修订稿走内部流程，不覆盖已发布记录 |
| 取消 | 非 published | 记录理由，取消未触发的相关普通任务；活动提醒按活动规则单独处理 |

发布载荷包括标题、正文、图片与顺序、视频成片、封面、字幕/音轨、对外活动规则。只修改内部备注或计划时间不使内容审核失效，但须重新检查依赖。重复平台笔记 ID 不能关联两个不同发布记录；同篇外部修改用 publication revision，重发为新 ID、新记录。

已发布修订的具体实现：新建关联原 Content 的修订工作项（supersedes_content_id），从 draft 再走内部流程；原 Content 保持 published。外部实际修改完成后，通过 PublicationChange 关联新批准版本，修订工作项记为 published，不创建同笔记 ID 的第二条 Publication。Publication 保留初次发布版本，另用 current_revision_id 指向当前外部确认版本；历史表现仍归同一笔记，修改前后比较需注明版本变化。外部重发则创建新的 Publication。

审核状态：pending/approved/rejected/withdrawn/stale。采用版本号条件更新；审批和编辑并发时只有一个符合预期版本的事务成功。已批准版本不可原地编辑，提交/通过记录不可删除。

复盘状态：not_due/awaiting_data/ready/drafted/reviewed。由实际发布时间和数据完整性派生。AI 报告可在数据不足时为 partial，不能把 partial 当 complete。

## 3. 选题、资产和导入

选题：proposed/accepted/rejected/expired。来源过期不删除已采纳内容，改显示“需重新核验时效”。同一选题默认采纳一次；另做变体必须明确“创建变体”并关联父题。

资产的业务状态和处理状态分离：

- business_status：pending_confirmation/usable/retired。
- file_status：uploading/ready/failed/quarantined。
- preview_status：not_requested/processing/ready/unsupported/failed。

预览失败不等于源文件损坏；源文件未完成不能发布。可将待确认资产关联草稿，提交审核前需要内部人员确认可用或移除。停用阻止新内容审批，并标记旧内容受影响，不自动删除历史发布。

数据导入批次：uploaded/parsing/needs_confirmation/committing/confirmed/partially_confirmed/failed/reverted。行状态：valid/conflict/unmatched/excluded/confirmed。部分确认只提交有效且被人选择的行；剩余保留待处理。撤销产生失效记录而非无痕删除，受影响看板和报告标为需要重算。

## 4. 活动状态

draft → scheduled → drawn → announced；另有 paused/cancelled。scheduled 表示活动时间已确认且启用提醒，不代表帖子已发布；帖子未发布时到点提醒指出“活动尚未核实发布”，不指导直接开奖。

逾期是派生标记：现在晚于 draw_at 且 scheduled，显示 overdue。drawn 仅等待公布，不再提示“未开奖”。paused 恢复时重新计算有效提醒；cancelled 不再触发提醒。标记 drawn 必须有实际时间、操作者、结果记录；announced 必须补公布链接或记录。撤销误操作仅管理员可操作，填写原因并保留前状态，不物理删除。

## 5. 通知与任务

通知：unread/read/superseded，送达：pending/sent/failed。任务完成是关联业务对象的状态，不等于 read。通知按用户隔离；一人已读不让另一人已读。开奖任务确认完成后，所有相关待发提醒失效；已发通知继续可查看历史。

## 6. 跨对象一致性

内容确认、发布登记、活动变更、数据确认均使用数据库事务与审计记录。事务内记录后续任务事件，事务外 worker 执行，避免“业务保存成功但提醒未建立”。归档、成员离职和资产停用必须保留引用；移除活动负责人前先指定接替人，否则转管理员并产生待办。

## 7. 支撑状态补充

Job/CollectionRun：queued/running/succeeded/partial/failed/cancelled。UploadSession：created/uploading/completed/expired/aborted/failed。CalendarEvent：planned/completed/cancelled，逾期派生。ReminderOccurrence：pending/processing/fired/skipped/cancelled/failed；跳过须有原因。Publication.lifecycle：active/deleted，删除保留历史。Feedback.status：new/triaged/archived。MetricObservation.validity：confirmed/superseded/reverted；识别待确认值仍在 ImportRow，不提前进入有效观察。

SourceConnection.health：unverified/healthy/degraded/auth_required/rate_limited/unavailable/disabled。Report.status：draft/partial/final/stale。BrandRuleSet：draft/active/retired。StrategyMemory：proposed/active/retired。其余业务枚举保持前文定义，不以 UI 中文名另建状态。
