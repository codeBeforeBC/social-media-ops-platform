# 13 · 实施计划与运维交接

v1.0｜2026-10-06。按可验收结果拆分，适合一个开发顺序推进或团队分工。每项需负责人、估时、实际进度和验收证据；本包不虚构工期报价。

## 环境与配置交接

开发、测试、生产独立数据库与对象存储前缀。配置项至少包括：域名与 HTTPS、登录方式、用户角色、存储、签名地址有效期、文件上限、预览资源限额、任务并发、时区、来源频率与凭据引用、AI/OCR 服务、单次/每日预算、日志期限、备份位置、提醒扫描间隔。

密钥通过部署环境的密钥管理注入，不写文档、截图、前端包或日志。给负责人一份只有配置名称、用途、管理位置和轮换方法的清单。AI 预算未配置时不得开无限制生产任务；可保留带限制的测试模式。

生产服务包括 Web/API、持续运行的任务 worker、提醒调度、数据库、私有文件存储；不能依赖设计师电脑或浏览器一直开着。数据库变更须有版本、升级验证与备份；有损迁移必须单独评审。

## 监控与处置

| 信号 | 处置 |
|---|---|
| 来源连续失败/认证过期 | 暂停相应连接，通知负责人，重新验证后恢复；其他来源继续 |
| 队列积压/worker 失联 | 检查租约和处理资源，恢复后按幂等键重试 |
| 提醒延迟或投递失败 | 优先恢复提醒 worker；从业务状态重算逾期，按 11 补偿 |
| 上传失败/磁盘不足 | 保留会话与已完成分片；阻止新上传并提示原因 |
| AI 成本超阈值 | 阻止新的高成本任务，已有人工编辑不受影响 |
| 数据导入错误 | 撤销批次、标记旧报告过期；不直接手改数据库掩盖错误 |

监控面板显示最后成功采集、待处理任务数、失败任务、提醒延迟、对象存储容量与预算消耗。告警的负责人和备用负责人必须在上线记录中写明。

## 备份、恢复、回滚

建议基线 RPO 24 小时、RTO 4 小时，须通过真实演练确认。数据库备份与对象版本/清单必须覆盖同一恢复点，检查资产引用和发布记录；恢复后重新计算提醒，不照搬旧队列盲发。

上线前记录应用版本、数据库版本、规则/提示词/模型版本及变更。回滚优先回应用并保持向后兼容数据；不可逆迁移通过经过演练的恢复程序处理。回滚后复查来源任务、通知去重、文件访问、导入状态。

## 开发最终交付清单

源代码与依赖锁定、部署说明、环境配置模板（无密钥）、实际接口说明、数据库迁移与字典、来源验证报告、媒体兼容报告、测试与 AI 评估结果、备份恢复演练、监控与责任人、管理员操作说明、用户操作说明、已知限制清单。

上线后观察建议：先记录一周实际制作产能和数据完整度，再设置实验节奏；按栏目、内容形式、制作工时及可获得的涨粉归因复盘。小样本阶段保留假设，不把单篇高点赞自动升级为永久策略。
