# 11 原排期日历与活动模块取消说明

v1.2｜2026-10-09｜[CHANGE-008 / ADR-008](../decisions/ADR-008-删除排期日历与活动.md)。保留原路径用于历史追溯，不再定义当前日历或活动功能。

## 全部取消

R08/R09及其相关R02/R14能力退出：月/周/列表日历、运营事项、计划发布、依赖/冲突/拖拽改期、AI排期建议及采纳；活动建档/规则/负责人/时间/状态、原帖关联、奖品和参与方式；开奖/公告及凭证、到期/逾期待办、提前/到点提醒、改期去重与停机补偿；笔记的活动标记/筛选和发布后的自动数据回收节点。

Campaign、CalendarEvent、ReminderRule、ReminderOccurrence、排期建议及campaign_evidence文件用途不再属于目标模型。不能改名为普通事项、运营任务或提醒中心继续实施。实际制作、发布、活动执行和时间安排均在系统外完成。

## 仍然保留

三类来源的定时采集配置、scheduler的采集/Job派发/上传过期清理、任务租约/重试/取消、通用系统通知/审计继续保留。系统通知仅服务于来源异常、任务、导入和报告结果/失败，不包含活动到期提醒。

独立Publication只登记已发布笔记身份、实际时间、标题/形式/流量类型；登记不产生回收或提醒事件。24小时/7天仅为已有数据的可选分析窗口，没有对应观察则显示缺失，不开发定时回收流程。

## 实施及验收影响

S6-01至06全部取消；稳定编号和旧判据保留，不记DONE。T10/T11/T12取消，不计PASS；IN-07/V07退出，不再索取开奖/触达输入。S8/S9不再依赖S6。

现有日历占位导航、提醒执行池/诊断、is_campaign字段及待消费publication.recorded回收事件由S11-01/03/04清退；保留迁移历史、通用通知与来源调度。实际清退需T25/T26及保留任务回归，详情见ADR-008和开发进度。本轮未删除代码、执行迁移或清理历史数据。
