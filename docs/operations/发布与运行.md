# 固定版本交付与运行

2026-10-13，S9交付说明；[CHANGE-009 / ADR-009](../decisions/ADR-009-仅支持arm64容器交付.md)将容器交付与验收收口为linux/arm64，amd64不再受支持。实际验收状态只在[开发进度](../tracking/开发进度.md)，证据见[S9](../evidence/s9/README.md)。当前是本地发布候选，不是已对外发布。每个实例使用者负责登录恢复、数据确认、模型费用、告警和每日备份；多人时在成员设置完成责任移交，停用成员前指定具备对应权限的接替人。

当前实际运行验收目标按用户2026-10-13确认（CHANGE-010）为本机Apple Silicon Mac/Docker Desktop。已测Docker虚拟机10CPU/约7.75GiB，应用等容器合计4 CPU/4.5GiB上限；5并发用户、1万线索/1千笔记/10万指标下通过目标，见[实态](../evidence/s9/runtime-target-rc15.json)与[测量](../evidence/s9/performance-compose-rc15.json)。容器限额不等于最小宿主硬件；其他宿主、更小硬件及远端镜像下载不在本次证明范围。

## 使用入口

普通使用者需要Git、Docker Engine/Desktop（支持Compose至少2.24.4、Docker CLI/API支持按架构load/inspect/save，当前验证Docker Desktop所带版本）和足够磁盘，不需要宿主Node或数据库。源码入口仍是仓库根目录`docker compose up -d --build`。固定版本包由维护者提供；镜像包位于受限`.local/releases/`，发布仓库及下载地址未授权，不填写不存在的链接。

当前候选为0.1.0-s9rc15，冻结源码91798c2。维护者构建下一版本示例：`node tools/s9/release.mjs 0.1.0-s9rc16`（版本/目录必须新建，不覆盖已存在候选）。当前仅生成linux/arm64包，加载入口拒绝amd64；历史双架构包保持原样。脚本先冻结含未提交实现文件的source副本，再从同一副本为arm64构建app和安全解析器，检查原生模块及模板，将固定digest的PostgreSQL、SeaweedFS、Caddy一同打包。已有指定架构/digest的缓存经RepoDigest核对后复用，缺失才拉取，不把浮动标签当缓存依据。manifest保存版本、Git基线、逐文件及完整源码SHA256、arm64镜像ID及文件SHA256。构建目录必须新建，失败产物留存，不复用为已验收版本。已有rc3只记录tracked diff；rc4构建期间增加S0工具，不作为最终源码一致的验收候选。source不含忽略的私有配置或业务证据；未构建候选不称已验收。

解析器要求目标Linux内核支持Landlock及seccomp，缺失时安全拒绝解析。历史amd64/QEMU不实现Landlock，rc3模拟运行失败的记录保留；CHANGE-009已取消amd64支持及其复验要求，不再等待该环境。已有arm64原生运行证据按其候选和实际范围保留。Docker能启动镜像不代表沙箱可用，不关闭安全隔离解决模拟器限制。

从提供的包目录加载arm64包并启动（受支持的linux/arm64环境，例如Apple Silicon Mac的Docker Linux虚拟机；Intel/AMD宿主不在当前容器支持范围）：

```sh
sh tools/s9/load-release.sh arm64
cp .env.example .env
docker compose --env-file .env --env-file release.env -p yoyo-use -f compose.yaml -f compose.release.yaml -f compose.https.yaml -f compose.release-https.yaml up -d --pull never --wait
```

加载前核对维护者提供的SHA256及manifest，加载脚本再检查tar与每个镜像ID，生成不含秘密的release.env，不覆盖已有配置。镜像tag固定到版本和架构；不要在升级前重新指向其他镜像。Compose release入口取消全部build和源码脚本挂载，初始化脚本已经在app镜像内。使用、开发、测试分别指定项目、卷、数据库及账号；不要把合成种子写入使用实例。默认所有服务只有HTTPS3443暴露在127.0.0.1，DB、私有存储和解析器不开放宿主端口。

打开`https://localhost:3443`。本地Caddy CA不自动写入宿主系统信任；由使用者按自己的环境核对并信任本实例根证书，或给浏览器配置受限测试信任。根证书可用显式管理命令导出：

```sh
docker compose --env-file .env --env-file release.env -p yoyo-use -f compose.yaml -f compose.release.yaml -f compose.https.yaml -f compose.release-https.yaml cp proxy:/data/caddy/pki/authorities/local/root.crt ./yoyo-local-root.crt
```

根证书不是私钥。首次管理员凭据用同一Compose参数`exec api node dist/tools/setup-token.js`在本机查看，勿写日志；首次设置成功后入口关闭。初始化/邀请不提供公共密码，实例凭据持久存储于state卷。

## HTTPS与外部能力

HTTPS_ORIGIN必须与浏览器Origin完全相等，默认`https://localhost:3443`；改端口时同步修改HTTPS_PORT和HTTPS_ORIGIN。公网部署需实际授权、域名DNS和端口可达性，在`.env`配置YOYO_DOMAIN、HTTPS_PORT=443、HTTPS_ORIGIN=https://实际域名、HTTPS_BIND以及YOYO_TLS（受控证书/ACME配置）。443的Origin不写`:443`。公网证书、域名及防火墙本轮未实测，不把本地CA演练冒充公网上线。

代理只在一跳隔离入口下启用TRUST_PROXY=1，保持生产Secure/HttpOnly/SameSite会话。导入与证据私有签名经同一HTTPS来源转发，保留Host和原路径；不把签名、Cookie或请求URI写入代理普通日志。Caddy配置依据[官方代理说明](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy)与[证书说明](https://caddyserver.com/docs/caddyfile/directives/tls)，本地CA信任由实例使用者管理。

AI默认禁用；按已有stdin配置入口写入`/state/ai.json`（0600），不把API key放.env或镜像。不限预算授权只属于当前本地使用者，clone实例须自己的选择；有限额度需核对价格/币种，历史未知费用不能当零。模板、手工录入和笔记登记不依赖模型。

小红书仍依赖宿主Node、固定OpenCLI1.8.8、浏览器Bridge与本人登录，见[S3运行说明](../evidence/s3/S3运行说明.md)。SOURCE_BRIDGE_URL填写授权宿主地址，容器SOURCE_BRIDGE_TOKEN_FILE为`/state/source-bridge-token`；将宿主受限token通过stdin写入state，不放明文环境。修正后的适配器在TOKEN为空时读取TOKEN_FILE；文件缺失/空白返回ADAPTER_UNAVAILABLE，非空显式环境配置保持兼容。宿主Bridge的监听仅按明确网络范围设置，浏览器/宿主离线时该来源暂停，恢复后验证；不复制Cookie给容器。Linux可配置host.docker.internal映射或实际可达节点，必须在目标环境核验。当前Bridge状态以环境报告为准；单独Bridge在线不表示每个来源已验证健康。

宿主执行`pnpm sources:bridge`后，将token经stdin配置到明确实例（在交付包目录执行，下例项目名必须对应自己的实例）：

```sh
docker compose --env-file .env --env-file release.env -p yoyo-use -f compose.yaml -f compose.release.yaml -f compose.https.yaml -f compose.release-https.yaml exec -T worker node -e 'let value=""; process.stdin.on("data",c=>value+=c); process.stdin.on("end",()=>{const fs=require("node:fs");fs.writeFileSync("/state/source-bridge-token",value.trim(),{mode:0o600});fs.chmodSync("/state/source-bridge-token",0o600);});' < /宿主受限目录/source-bridge-token
```

此命令不显示token。配置后先验证连接再开启定时，未知能力/剩余额度保持未知。Bridge的loopback健康检查与容器读取实际公开来源分别验证，不能用健康响应代替三类来源验收。

## 备份、监控与升级

每日至少一次且升级前执行一致备份，目标RPO≤24小时/RTO≤4小时需恢复演练留证；尚未演练不能宣称达标。独立保存副本并限制目录访问，不提交业务数据或凭据。

```sh
# 同一命令环境须保留release.env中版本/架构；脚本只接受明确项目和新目录。
set -a
. ./release.env
set +a
sh tools/s9/backup.sh yoyo-use /受限目录/新的备份 compose.yaml compose.release.yaml compose.https.yaml compose.release-https.yaml
```

脚本停止业务/解析/存储写入，取得pg_dump、objects、state及本地CA同恢复点，记录SHA256并恢复之前正在运行的服务；失败也尝试恢复先前状态，不覆盖旧备份、不删除卷。备份窗口内API暂不可用，避开人工确认操作。备份目录含秘密，chmod700/文件600，不输出其内容。代理config可从已审查Caddyfile再生，CA私钥在proxy-data副本内。

恢复到全新项目（保持同一版本/架构，备份目录应是受限完整一致点）：

```sh
sh tools/s9/restore.sh yoyo-recovered /受限目录/完整备份 compose.yaml compose.release.yaml compose.https.yaml compose.release-https.yaml
```

目标项目必须没有既有容器/卷，且配置不得指向外部或别的项目的持久卷；已有使用项目拒绝覆盖。校验和、目录穿越/归档链接、卷是否已有数据在恢复前检查；Docker镜像复制出的空目录不算既有数据。pg_restore后先ANALYZE再启动应用，避免缺统计使规模查询超时。恢复成功只代表服务就绪，须核对笔记身份/指标更正/证据哈希/任务及实例凭据后再启用业务。失败项目/卷保留，修复后用另一个明确新项目重试，不清卷掩盖失败。

旧测试网络可能耗尽Docker默认地址池；仅在确认测试项目无人运行后释放其网络，保留卷/备份/配置，重启旧测试项目时由Compose重新创建网络。不要清理dev或用户自有网络。

管理员在运行设置检查一般/media/scheduler心跳、队列年龄、失败原因、来源健康、用量和预算；站内通知与已读不是业务完成。使用者日常检查Compose健康和备份校验；外部告警通道未配置时明确为人工值守，不假称已发送告警。

升级先备份、停旧写入、加载已核验的新包、按同一项目启动受控迁移。SQL001–036保持校验和，迁移失败阻止应用就绪。普通stop/start和容器重建保留卷；不要用down -v或reset清除使用数据。应用回滚不等于数据库可降级：只能使用兼容构建，或停写恢复对应数据库/objects/state备份点，丢失点之后变更须明确说明。旧生产/日历/活动/回收任务不恢复执行。

完整恢复/性能/干净环境与真实业务验收按原依赖进入S9-02至06。当前说明和候选包不替代后台OCR、真实导入或17项发布门禁。
