# 首版验收交接入口

本文件说明使用步骤和证据范围，不维护第二套任务状态；当前事实以[台账](../tracking/开发进度.md)和[最近交接](../tracking/开发日志.md)为准。当前候选rc15的335文件冻结于91798c2，rc11/12保留历史；按[CHANGE-009 / ADR-009](../decisions/ADR-009-仅支持arm64容器交付.md)仅使用linux/arm64本地交付包；未推送/公开发布。

## 使用者操作

1. 按[发布与运行](发布与运行.md)加载arm64架构包、配置项目/端口、启动和信任该实例证书。在本机取得初始化凭据，网页创建管理员。
2. 工作区设置登记平台内部账号ID；展示昵称/平台展示号先核对对应关系。邀请成员并分配角色，移除负责人前完成责任移交。
3. 选题策划设置来源范围、宿主Bridge和调度；失败看原因，历史内容不代表新采集。来源证据可核对后再生成/采纳选题，采纳只记录决策。
4. 数据复盘登记实际已发布笔记，核对ID、链接、账号、图文/视频和发布时间。平台制作/发布在系统外；历史登记不表示由本次选题生成或刚刚发帖。
5. 上传后台截图/表格，核对原件、OCR低置信和漏识别、账号/笔记、时间、单位/流量口径，手工选区/更正后只确认所选行。未确认不进入正式计算；缺失不填零，组合值不拆分。
6. 更正建立新修订并保留来源；撤销早期批次不覆盖后续有效支持。复盘报告区分partial/final/stale，策略先人工提案再激活；无数据不能据此判断增长或因果。
7. 反馈许可未知/仅内部不生成公开草案；撤回后旧草案与引用退出。系统没有发送入口。每日检查任务、来源、费用已知状态和备份校验，按运行说明保存受限副本。

## 发布门禁与解除条件

执行 `node tools/s9/release-gates.mjs` 只检查唯一台账的8项P0、17项适用T、前置状态、重要缺陷及链接。退出2表示门禁未关闭；它不替代业务验收，也不给S9-06添加自身依赖。实际结果见[派生门禁报告](../evidence/s9/release-gates.json)。

当前还需要：合法真实视频后台样本及其稳定身份/时间/单位/缺失映射，已取得真实账号XLSX，首表部分映射可用、六趋势表未导入；用户已确认当前本机为实际目标，rc15资源上限/桌面键盘/来源恢复已有证据，amd64及另一专用宿主不再等待；日常备份RPO与完整真实原依赖验收。T03/T24单项通过不表示全版通过。公网/镜像仓库发布按另行实际授权执行。

目前全部临时S9/OCR实例已停止，卷、私有捕获、备份和失败现场保留；原开发DB54329、存储59000、解析59010继续运行。产品AI仍禁用，隔离评估原配置保持0600；本轮临时配置删除。机器重启/浏览器离线后，先复核Bridge及服务，不把旧健康记录当当前实态。
